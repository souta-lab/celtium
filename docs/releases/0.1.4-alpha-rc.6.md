# Celtium 0.1.4-alpha-rc.6 — crash breadcrumbs

Same build as rc.5 (legacy immediate routes stay off) plus a diagnostic that makes the
tester's black screen reportable.

## Why

The black screen is a device loss: RADV reports `GPUVM fault detected at address
0x800101a00000`, `CELTIUM_VULKAN_DEVICE_LOST` follows, and every later present skips
(`lastSkip=[no frame target, or stalled]`), which is why the picture stays black - a lost
device has nothing left to present. The same address appears in both of the tester's logs,
so the fault is deterministic, but it does not reproduce here: the same JAR, instance and
mod set at 854x480 and 1920x1080, under Xwayland and native Wayland, with the Khronos
validation layer on, present every menu frame with no device loss and no VUID message.

The log's own lines around the fault are texture dumps and a loading-bar quad, which are
not the faulting call. This build keeps a ring of the last 96 renderer operations (windows,
terrain passes, chain pairs, texture uploads) and prints it **only when the device is lost**.

## How to use it

Launch with both flags added to the JVM arguments:

```
-Dceltium.vulkan.crashBreadcrumbs=true -Dceltium.vulkan.validation=true
```

The first makes the ring; the second turns on the Khronos validation layer, whose messages
name the invalid object before the fault. A session that does not lose the device prints
nothing and is not slowed in any way that matters (the ring is one array write per
operation); a session that does prints

```
CELTIUM_CRASH_BREADCRUMBS trigger=... count=N
CELTIUM_CRUMB #0 ... (the operations before the device loss, oldest first)
```

Report the `CELTIUM_CRUMB` lines (and any `VUID-` lines) with the log. The last few crumbs
are the operations to look at.

## Also in this build

- Legacy immediate routes (`glBegin`/`glVertex3f`/`glTexCoord*`) stay off (rc.5 bisect):
  the loading screen's progress bar is not drawn; `-Dceltium.gless.legacyImmediate=true`
  re-enables it.
- The raw-write refresh now also skips released wrappers (image/view/sampler cleared by a
  resource reload) instead of throwing per batch.
