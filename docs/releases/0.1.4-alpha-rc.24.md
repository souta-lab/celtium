# Celtium 0.1.4-alpha-rc.24 — the retire queue waits for the recording to close

Enabling the validation layer on the tester's own launch named the black screen: `VUID-vkEndCommandBuffer-commandBuffer-00059`,
a command buffer invalidated because two images and a framebuffer bound to it had been destroyed. The retire queue
only asked whether every *submission* had completed - not whether a command buffer was still being recorded. A frame's
buffer is recorded, and its windows already name framebuffers and images, long before it is submitted; a flush in that
gap destroyed exactly those objects, and the next submission took the device down with it (RADV GPUVM fault), leaving a
black window that kept running.

`celtium$recordingOpen()` (`frameBufferOpen || immediateWindowBusy`) now gates the two mid-frame retire drains. The
teardown drains keep their rule, because teardown settles the GPU with no recording open.

The same launch also confirmed the announcement diagnostics shipped in rc.20-21 work: the atlas extent matched, no
copy was refused, and the fault came after the upload, not inside it.
