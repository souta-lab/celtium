# Celtium 0.3.0-rc1 — Windows でのエンティティ描画修正

*Released 2026-11-16 · tag [`v0.3.0-rc1`](https://github.com/souta-lab/celtium/releases/tag/v0.3.0-rc1) · previous [`v0.2.2`](https://github.com/souta-lab/celtium/releases/tag/v0.2.2)*

リリース候補。Windows では、クライアントメモリから描かれるエンティティやプレイヤーのモデルが描画されず、
影だけが残る不具合があった。本候補はその原因である読み取り範囲ガードを修正する。Windows 実機での
確認がまだのため rc とする。

## Fixed

- **Windows でエンティティとプレイヤーのモデルが描画されるようになった。** GL スタブのクライアント
  ポインタ fault guard は、読み取り可能なメモリ範囲を `/proc/self/maps` から判定していたが、これは
  Linux にしか存在しない。そのため Windows では、owned buffer の公開で覆われないクライアントメモリ
  からの描画がすべて拒否され、自前ダイレクトバッファから描くモデル（EfficientEntities の
  `ModelBiped` / `ModelPlayer`、`ModelSlime` など）が一切表示されず、BufferBuilder 経路で描かれる
  影だけが残っていた。
- ガードは OS 非依存の読み取り範囲チェック（`ReadableMemoryRanges`）に置き換えた。Linux は従来の
  maps パーサのままで挙動不変、Windows は `VirtualQuery`（FFM）でコミット済みかつ読み取り可能な
  領域を解決する、その他の OS は従来どおり既定で拒否する。Windows のバインドに失敗した場合は
  従来どおり拒否へ安全に劣化する。ガードの他の呼び出し箇所（drawElements のインデックス/頂点、
  split-array repack）も同じ入口を通るため同様に恩恵を受ける。
- 回帰テストは、範囲演算、Windows の保護属性と領域歩行（フェイク関数で検証）、スタブの受理/拒否を
  カバーする。`celtium-vulkan`: 94 suites / 459 tests、失敗 0。

## Known limits

- Windows 実機での実行はまだ。`VirtualQuery` の FFM バインド、census が readable ranges を報告する
  こと、EfficientEntities 環境での実際の描画とフレーム時間への影響は実機未確認。
