# Celtium 0.2.5-rc2

A release candidate on top of 0.2.5-rc1: a fix for the crash on creating a new world (issue #423), shadow loading moved onto the native path, dynamic lights, and terrain-draw performance work. This is an RC, published so the fixes can be verified on real hardware; it is not a final release.

## Fix: crash on creating a new world (issue #423, NVIDIA)

- This fixes the crash reported on 0.2.4, where the game died inside the NVIDIA driver (nvoglv64.dll) while a world was being created. On the path where another mod creates a framebuffer in the middle of a frame, Celtium's framebuffer cache could hand back a framebuffer that had been built for a frame target that no longer existed. Each cache entry now records what it was built over — the colour and depth views and the extent — and an entry that no longer matches is retired and rebuilt instead of being reused.
- Two related fixes ride along. If a frame target cannot be recreated to completion, the old target keeps being used (previously the recreation went ahead anyway and could leave references to destroyed views behind). And at world teardown, cache entries keyed by the render passes that were just destroyed are now always cleared.
- Stated plainly: the fix is verified by a code audit, unit tests, and the full module test suite in CI, but the reporting environment — a GTX 1650 Ti with a large modpack — is not available locally, so the final check has not been done on real hardware. Whether it is fixed on the reporter's machine is the deciding test; please report results on #423.

## Shadow loading now runs on the native path

- The shadow-pass loading that rc1 described as "not yet on the native path" now runs on Celtium's native path (measured on the validation fixture, AMD Radeon RX 6400: native depth copies served 8 or more times, refused 0).
- One limit remains: **shadows do not visibly darken the scene yet.** The shadow pass's terrain draws still land in the frame target instead of the shadow target. That is the next main item of work.

## Dynamic lights (at terrain shading time)

- VulkanMod-Next's D13 was taken in: terrain shading now reflects dynamic lights (a held torch and similar) inside Celtium itself, recorded in the "Built into Celtium" section of docs/mod-compatibility.md. An A/B on the validation fixture confirms the pixels around a light source actually brighten.

## Performance work

- Draw-list retention (D25): terrain batch assembly is retained across frames; on the validation fixture the terrain batch time went from 0.312 to 0.228 ms/frame standing still, and from 0.497 to 0.213 ms/frame while moving.
- Compact vertices (D23): the default vertex format is now 24 bytes, reducing vertex memory by 25% per vertex.
- The FPS KPI against Celeritas was again not re-measured (the real-pack measurement setup does not exist yet), and no performance superiority is claimed.

## Other fixes

- Shader program translation now assigns locations to modern in/out declarations, so programs that previously failed translation now go through.
- The release pipeline now re-validates the SPIR-V inside the shipped jar (a process change; no behaviour change).

## Continuing limits

- A stock Demonica jar still will not enable shaders against Celtium as-is, because Demonica's own QuarantineGuard pins the Celeritas jar's hash — as described in rc1.
- Visible shadow completion and the KPI re-measurement are the next main items of work.
