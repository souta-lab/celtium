# Celtium 0.2.4 — パフォーマンスリリース

*Released 2026-11-17 · tag [`v0.2.4`](https://github.com/souta-lab/celtium/releases/tag/v0.2.4) · previous [`v0.2.3`](https://github.com/souta-lab/celtium/releases/tag/v0.2.3)*

本リリースの中心は、Vulkan・common・forge122 のホットパス全体にわたる最適化（PR #421）である。実機
（AMD Radeon RX 6400、RADV）での測定で、validation レグの world FPS が 62.82 → 70.52（+12.3%）、
shipping レグが 212.10 → 237.58（+12.0%）になった。併せて、GL-less パスで起動そのものが落ちる
再帰バグの修正と、Demonica（Iris 系シェーダーパイプライン mod）との互換に向けた基盤一式を含む。

## Performance

測定はすべて AMD Radeon RX 6400（RADV NAVI24、Mesa 26.2.6-1、1280×720）の実機レグで、変更前後の
両方を同じ手順で取っている。

- validation レグ: world FPS 62.82 → 70.52（**+12.3%**）、`batchTimings` の総コスト −13.3% / offer、
  prepare ステージ −20.8%
- shipping レグ: world FPS 212.10 → 237.58（**+12.0%**）、`VulkanArena` の `uploadPhaseMicros[reserve]`
  16,002 µs → 4,996 µs（**−68.8%**）

内訳は、GLSL 変換の正規表現事前コンパイル化と primitive map 化、アリーナのフリーリスト化とアップロード
のバッチ化、テクスチャアップロードのストリーミング化（4K アトラスで 69 MiB の中間配列を除去）、
uniform 書き込みのゼロアロケーション化など。画質・描画内容の変更はない。

## Fixed

- **caps probe の相互再帰で GL30 が毒入りし、バニラの validation レグが起動できない**問題を修正。
  `CeltiumGllessHint` の capability probe が `GLContext.getCapabilities()` の遅延構築と再入し、
  StackOverflow でクラスが恒久的に壊れていた。再入ガードと完了フラグで対策した。
- Demonica 互換の基盤: コンテキスト生成条件に結びついた GL バージョン条項（core 指定時のみ 3.3 を広告）、
  SplashProgress の変換アンカー互換、フレームターゲットの遅延生成、テクスチャユニット数の是正
  （per-stage 32 / combined 64）、image unit の実装と台帳の拡張（8 → 32）。
- Demonica 互換サーフェスの機械検証: 出荷 jar のバイトコードから抽出した 125 クラス / 186 メソッド /
  53 フィールドのマニフェストを CI で照合する（Tier A）。`ChunkBufferBuilder` 等の欠けていた受け口を
  celtium 側の実装として追加した（Tier B）。

## Known limits

- **Demonica のシェーダーはまだ描画されない。** 互換レグ（RX 6400、Demonica 0.9.1 + Complementary
  Reimagined r5.9.3）ではパイプライン生成が image unit の割り当てを通過するところまで進んだが、
  draw buffer 数（現在 1 と広告）の壁で停止し、シェーダーは無効化される。影の描画も未検証。
  対応は継続中で、本リリースはその途中経過を含む。
- FPS KPI（対 Celeritas）の再測定は本リリースには含まない。上記の +12% は celtium 自身の前後比較である。
- Windows・macOS での実機描画確認は 0.2.3 から引き続き未実施（CI のテストスイートは 3 OS で実行される）。
