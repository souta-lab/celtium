# Celtium 0.1.4-alpha-rc.1 — SuperSymmetry and ATM3 bring-up

This prerelease is the first cut after RC8. It is a **test build**: it brings the two measured modpacks
(SuperSymmetry and All the Mods 3) to a state where they boot, render and can be measured under the
Cleanroom Relauncher setup, and it fixes several crashes and refusals those packs exercised. It does **not**
claim the performance goal: Celtium is still slower than Celeritas on both packs (numbers below).

## Changes

- **Crash fix in the texture upload path**: the upload path's `finally` block read a level record that can be
  absent (an upload refused before any level was captured) and threw `NullPointerException`, which turned an
  honest refusal into a composite failure with no named cause. Fixed and re-measured on SuperSymmetry.
- **32-byte particle layout**: a mod layout (position, UV, colour, short UV, byte normal, padding) that no table row
  answered is now drawn as the 28-byte particle layout it repeats. The uploader hands the backend a compacted copy,
  so the pipeline width and the submitted stride agree. A log marker (`CELTIUM_COMPACTED_BATCH`) names the path's
  first two batches.
- **Immersive Railroading's stride-48 client arrays**: the split texture/colour/normal pointer natives are now routed
  to the stub and a stride-48 draw is repacked into the 24-byte position/texcoord/colour layout. The measured draws
  now pass the layout stage and are gated by a *different* guard (the projection mirror), which is not fixed yet.
- **Mod-originated `glMultMatrix` and the GL matrix mode**: mod matrices can reach the mirror (caller-decided, no
  double application for vanilla's camera), and the matrix mode is kept outside the backend instance. Both are
  behind `-Dceltium.glless.modMatrixRoutes=true` because the caller test walks a stack and was measured at
  4.05 → 28.5–29.2 ms warm frame when the guard was unconditional; the default path is the fast one.
- **Fewer mirror refusals**: a framebuffer colour attachment no longer gets a content-less mirror built for it while
  the publication path is about to own its image (7 → 4 `PATCH_REJECTED` lines per SuperSymmetry run, no picture or
  frame-time change).
- **A per-frame chunk upload budget** (`-Dceltium.vulkan.uploadBudget`, default 0 = off) that queues finished outputs
  and drains them at the head of `setupTerrain`. Burst-only budgeting keeps the startup build unbudgeted and the
  capture valid; the measured gain (3.82 → 3.55 ms P50 on ATM3) is inside the run-to-run spread, so it stays off.
- **Diagnostics**: a present-cadence instrument (`-Dceltium.vulkan.presentInterval=true`, prints
  `CELTIUM_PRESENT_INTERVAL` with the frame period and fps where no frame boundary runs), and the frame budget's
  periodic dump no longer forces a presented-image readback (`-Dceltium.vulkan.presentedDumpEvery=0` is the
  documented way to measure without that tax).

## Validation state

Linux / AMD RX 6400 (RADV), 1280x720 headless, Cleanroom Relauncher 1.3.0 → Cleanroom 0.7.14-alpha, Java 8 parent /
Zulu 25 game, unless noted.

- **SuperSymmetry** boots, loads a world and renders. World-only warm frame (200 ticks, fixed camera, no presented
  readback): **Celtium 2.50 ms** P50 (P95 4.61) against **Celeritas 1.68 ms** (P95 2.35), i.e. 1.48× — two
  repetitions each, reproducible to within 0.03 ms.
- **All the Mods 3 6.1.1** (249 mods, the migration gist's removals/additions applied) boots, loads a world and
  renders: **Celtium 3.82 ms** P50 (P95 15.9) against **Celeritas 1.44 ms** (P95 4.85), i.e. 2.65× median over
  three repetitions each. ATM3 needs an 8 GiB heap; 5 GiB ends in CraftTweaker's recipe build with
  `OutOfMemoryError`.
- **No Vulkan validation errors and no device loss** in the SuperSymmetry and ATM3 runs above.
- Remaining refusals (SuperSymmetry): 4 mirror `PATCH_REJECTED`, 1 `COMPOSITE_REFUSED` (a sampled texture that was
  never allocated), 3 `CAPTURE_MISS`, 8 Immersive Railroading stride-48 draws (projection mirror, above). Draw-level
  refusals reported by the verification summary are 0 for the world scene.
- Not tested here: Windows/NVIDIA (the RC8 device-loss report), Intel for this change set, or a real playthrough.
  ATM3's first-tester instance is the assembled `.celtium-work` instance, not a user-created one.

## Known issues

- Celtium is slower than Celeritas on both packs (1.48× and 2.65×); the remaining cost is the world draw path and
  the measurement is P50/P95 over a fixed scene, not a playthrough.
- The stride-48 Immersive Railroading draws still refuse: their matrices land on the wrong mirror stack and the
  projection guard then refuses the transform. `-Dceltium.glless.modMatrixRoutes=true` is the experiment, not a
  fix; it is off by default because of the cost.
- ATI/Intel Windows parity, GregTech bloom pixel correctness and the raw-FBO reattachment item from RC8 are
  unchanged.
