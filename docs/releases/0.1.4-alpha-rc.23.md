# Celtium 0.1.4-alpha-rc.23 — the splash canvases too

rc.22 made a texture's mirror be forgotten only after the queued groups that sample it have been drawn.
The splash's canvas invalidation was the second place a mirror is dropped and it kept the old order; it now
follows the same rule.

Measured on the menu leg (Unicode atlas, 1920x1080): windows 2.0 a frame, drawn 5 a frame, no device loss
and no validation messages, so the extra flush costs nothing there.

Black-screen status: two reports from the tester end on a mirror upload announced from the game's own
upload, a fixed GPUVM fault address, and a GL texture deletion immediately before it - one after a 256x256
announcement, one after the 4096x4224 font atlas, which is why the size hypothesis is out and the
delete-ordering one is in. rc.22 and rc.23 carry the ordering fix; the extent diagnostics from rc.20-21
name the copy if it still happens.
