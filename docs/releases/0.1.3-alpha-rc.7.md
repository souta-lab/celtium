# Celtium 0.1.3-alpha-rc.7 — performance and FBO lifetime fixes

Experimental build. Windows and NVIDIA GPU runtime verification pending.

## Performance changes
- Coalesce adjacent semaphore-free primary command buffers into a single VkSubmitInfo in each bounded submit chunk, preserving command-buffer order, original semaphore boundaries, and the existing completion fence.
- Report the actual number of driver submit-info records saved beside batched submit timing.
- Cache the reverse mapping from raw GL framebuffer color textures to owning framebuffer: fast O(1) lookups instead of scanning all active FBOs; a fallback scan recovers when a cached owner is detached.

## Correctness fixes
- Honor intentional explicit Windows -Dceltium.vulkan.asyncPresent=true again; RC6 accidentally overrode it. Windows default remains false.
- glFramebufferTexture2D(..., texture=0) now detaches the previous color-image mapping.
- glDeleteFramebuffers clears stale color-attachment associations and restores default bindings when deleting a bound framebuffer.
- Unit tests for Vulkan submission grouping and GL framebuffer detach/reattach.
- Retain RC5 fence protection and RC6 descriptor VkResult reporting.

## Validation and limitations
The RC5 Supersymmetry log (https://mclo.gs/Yv63NpH) contained 21,970 deferred command buffers in 2,077 batched flushes, and 7 failed GregTech Unreal Bloom passes immediately before device loss. This patch reduces real driver submission work and fixes actual FBO bookkeeping bugs. **The original GPU device-loss root cause and Neeyo's 10 FPS are not yet verified fixed on Windows.** A matched-scene FPS comparison and repeated Bloom test are required.

See https://github.com/souta-lab/celtium/issues/414 .
