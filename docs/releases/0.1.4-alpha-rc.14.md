# Celtium 0.1.4-alpha-rc.14 — the crash breadcrumbs are always on

The tester's black screen is a device loss, and the operations before it are what names the
cause. Those crumbs used to be opt-in, which is a step that can be missed in a launcher. They are
now recorded for every session, as numbers rather than strings: three array writes per operation
(a window's target and group count, a terrain pass, a texture upload with its extent, a raw write,
the coalesced copies), formatted and printed only when the device is actually lost.

A healthy session pays no visible cost and prints nothing. A lost device prints a
`CELTIUM_CRASH_BREADCRUMBS` line followed by named `CELTIUM_CRUMB` entries, so the next report
carries the diagnosis without a JVM flag. `-Dceltium.vulkan.crashBreadcrumbs=false` turns it off.

Menu smoke on this build: 3899 of 3899 presents, no device loss, no validation messages, no
breadcrumb output. The rest is rc.13 (reused window structures) with the canonical plain gate
PASSED.
