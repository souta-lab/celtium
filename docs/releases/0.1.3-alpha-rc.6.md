# Celtium 0.1.3-alpha-rc.6 — Windows presenter guard and device diagnostics

Experimental pre-release; Windows runtime is not yet validated.

## Findings

Neeyo's RC5 log https://mclo.gs/Yv63NpH confirms rc.5 was installed, but Prism retained an explicit Java argument enabling async Present. The GPU was lost following seven refused GregTech Unreal Bloom draws. RC5 prevented the previous native Access Violation; it did not prevent the underlying GPU error.

## Changes

- On Windows, ignore stale -Dceltium.vulkan.asyncPresent=true by default. Enable this known-unstable experimental mode only with BOTH -Dceltium.vulkan.asyncPresent=true AND -Dceltium.vulkan.unsafeWindowsAsyncPresent=true.
- Print CELTIUM_ASYNC_PRESENT_CONFIG at startup with effective setting, including a warning when a stale opt-in is ignored.
- Print bounded CELTIUM_DESCRIPTOR_VK_RESULT logs with the exact VkResult when a Vulkan descriptor pool/set allocation fails. The previous generic descriptor-creation-failed message discarded this key detail.
- On VK_ERROR_DEVICE_LOST during descriptor creation, stop without further native driver allocations; do not convert the fatal error to a recoverable missing texture.
- Add unit tests for effective Windows async policy and terminal descriptor VkResult.

## Verification

Build and automated tests are Linux-side only. GPU-loss root cause and slow FPS on Windows are not yet proven solved. The next controlled Windows test should keep all settings constant and confirm the effective async mode from the startup message. Compare FPS/frame times only after the device remains healthy. See https://github.com/souta-lab/celtium/issues/414 .
