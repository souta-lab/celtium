# Celtium 0.1.4-alpha-rc.10 — no exception per raw write

One error-path fix since rc.9, found by profiling rc.9's world leg.

The only client-thread exception source in that profile was `requireOwned` inside
`uploadFromGlTexture`, one stack fill per raw write, with GregTech's bloom post-processing on
the stack: it renders into a framebuffer and samples the colour texture, whose mirror shares
the renderer's image. The predicate that refuses exactly that (`celtium$ownsImage`) sat after
the branch for GL names past the tracked bound, and a mod that allocates many textures - bloom
allocates one per frame - has names past it. Those writes therefore skipped the check, reached
the upload, threw, and paid the ordering flush before throwing.

The check now runs before that branch, so every path that reaches an upload has an image the
wrapper may write. Profile after the change: raw-write path 11.1% -> 8.3% of client-thread CPU,
exception stack fills 2.6% -> 0.6% (the rest are other caught paths).

Susy world leg on this build: warm P50 2.66 ms, no refusal markers, no validation messages, no
device loss, no lazy-mirror failures.

Nothing else changed from rc.9.
