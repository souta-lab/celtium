## Celtium 0.3.0

375 commits (167 landings), 372 files, +33,110 / −8,258 lines since 0.2.5. The bulk is three waves of GL decoupling from Celeritas (PRs #426–#428), the 2026-11-21 all-out campaign (every one of the ~87 findings from a code audit was triaged and disposed of), and a large step forward for the shader-pack route on the in-core pipeline. The dynamic-lighting gain is measured. Pack shadows now run end to end — pack terrain programs translate and draw — but darkening in the presented image is not yet measured; the "Shadows" section states the current position honestly. The test suite grew to common 119 / celtium-vulkan 1,064 / forge122 50 (combined gate at version freeze).

### Fixed

Crashes, hangs, lifetime:

- GPU resources owned by a retired device could be released twice after device loss, a native-crash path (item 529 family).
- Swapchain acquire retried forever on repeated failure; the acquire side now raises the failure upward.
- If swapchain creation keeps failing, the client now escalates to a crash report at a cap instead of hanging on a silent black screen.
- Double destruction of a Vulkan context that never owned a device.
- Command-buffer release now defers fences that still point at live submissions.
- An exception in the render-section occlusion search could leave the inFlight flag set and freeze the frame.
- Deferred cleanup destroyers could run on a successor device.
- Repeated waits on the same fence under queue contention could stall progress.
- A failing teardown during renderer reload (resource reload) is now recorded and the new renderer is still created, instead of the teardown failure turning into a crash (hardening from the #425 report).
- A graphics-device creation failure now bundles the result code, device name, enabled extensions and features, and the previous in-process device-loss record into the error, so the cause can be approached without a reporter round-trip (hardening from the item 529 report).

Rendering and display:

- Validation error when a depth texture was used as a color target (the DEPTH form of VUID-09600).
- Chain-pair color attachments lost their layout publication, producing validation errors 00344 / 00900 (measured 20 → 0).
- Distant leaves rendered see-through (the leaves quality setting never reached the translucency path).
- Vertex normals were always bypassed due to reading the wrong settings class.
- The green component of the fog color was missing from the fog computation.
- Cloud color and brightness were always white because the cloud color publication was missing.
- The font atlas reused names across generations, a source of garbled text.
- The spawn-portal animation did not take its proper purple color.
- One cause of item-frame maps not rendering (a name-resolution mismatch for DynamicTexture).
- A bit collision in the light-cache key swapped brightness at negative Z coordinates.
- On integrated GPUs, draw-range vertex indices were not widened to 32 bits and rendering broke.

Mod / GL compatibility:

- A compatibility break where a field that mods write by name had been removed, breaking mod initialization (Demonica).
- Rendering-API gaps reported from the threads (glGenBuffers / glBindBuffer / glBufferData and friends).
- Mod program link status (LINK_STATUS / VALIDATE_STATUS) and info logs are now answered from the actual link result, on both the LWJGL2 and LWJGL3 paths. They previously reported success unconditionally, so a program that failed to link could vanish silently.
- Block rendering is routed through BlockRendererDispatcher again, restoring compatibility with mods that replace the dispatcher (a port of the upstream Celeritas change).

### Dynamic lights (item 430)

- Fixed the root cause of dynamic lights not affecting terrain (the camera subtraction was applied twice).
- **The gain is measured.** In a dark scene (koenigsegg-agera, Intel HD Graphics 620, torch fixture scene, one run per arm), floor-center luminance went from OFF 28.62 to ON 52.28 (+23.65). Controls: sky +0.06, stone top +0.31, floor left edge +2.31; full-frame mean 29.99 → 35.52. Only the floor near the light source rises, the distance does not — the correct falloff shape.
- These are functional-run numbers on HD 620, not a performance yardstick on RX 6400.
- The funnel census (FUNNEL_SUMMARY) is now also printed at world exit; it previously depended on a JVM shutdown hook and never reached the harness log.

### Shadows: real packs run on the in-core pipeline. Darkening not yet measured

- The gbuffers terrain programs of Complementary Shaders / BSL are translated and bound into the terrain pass on celtium's in-core pipeline, without GlStub, and reach drawing (terrain program draws confirmed in real runs).
- The fix for the presented image collapsing to a single-color void (a pre-transform wrongly applied to mod programs) is in. Together with the terrain color publication fixes, the COLOR-form validation errors 00344 / 00900 measured 20 → 0. The DEPTH form of 09600 is disposed of; in the last runs before this version was frozen, 09600 measured 0 with BSL and 10 remaining with Complementary (this is not written as resolved).
- **However, darkening as a shadow shape in the presented image is not yet measured.** In the last runs before the freeze (koenigsegg-agera, Intel HD Graphics 620), BSL presented pitch black, and Complementary showed stone pillars and a floor in fog — with no stone texture, no sunlight lit surface, and no shadow shape on the floor.
- Where the triage stands: a G-buffer readback measured that, in both packs, the terrain fragment writes exactly (0,0,0,1) as albedo. The color dies at the fragment's write, not on the deferred read side. The remaining discrimination is the fragment's input side (attribute matching); the fix goes to the next release.
- The in-core terrain shadow lookup (the terrain shader sampling the routed shadow pass depth) also remains in the tree, but its darkening on its own is likewise not measured.

### Performance

- Several waves of optimization landed: hot-path allocation cuts, growable descriptor pools, viewport/scissor reuse, a particle repack cache, and more. Font atlas consolidation is implemented, but no measured gain is claimed for it.
- Controlled measurement (generated-world flight scene, koenigsegg-agera / Intel HD Graphics 620, 1280×720, render distance 12, warm window): celtium frame-time P50 measured 16.55 / 19.04 / 19.00 ms across three runs (363 / 331 / 335 frames). Celeritas on the same scene measured about 8.1 ms — on this scene and this GPU a gap remains. A re-measurement on main after the pack publication fixes also gave P50 17.27 ms (333 frames): no regression from the campaign's changes.
- The measurement path itself was fixed: the present-readback diagnostic switch never reached the harness configuration. Early informal comparison figures were taken with that readback running on every frame and are withdrawn as product numbers.
- These are functional-environment numbers on HD 620, not a performance yardstick on RX 6400.

### Compatibility

- **VanillaFix coexistence confirmed** (its startup crash was triaged and resolved).
- **FoamFix 0.10.15 coexistence confirmed** (RX 6400, fixture runs with healthy presented images). Note that FoamFix's fast animated-texture path does not engage in this stack — Cleanroom's LWJGL2 layer does not advertise OpenGL 4.3 / ARB_copy_image, so FoamFix itself falls back to the slow path. celtium's glCopyImageSubData wiring and its unit pin are in.
- **Particle Culling is compatible.**
- A raster occlusion culling (useRasterOcclusionCulling) ON/OFF comparison run showed no section-shaped holes (the presented-image difference was only mob positions and poses over time).

### Diagnostics and internals

- The terrain pass GPU time (the terrainGpu column) now actually returns values in real runs. The readback previously read the newest frame's unconfirmed state and always collapsed to 0.0; it is now snapshot-based per submission, and real values in the summary were confirmed in a real run (agera, generated world).
- The ledger cost of upload reservations (reserve) can now be measured separately from the upload-time totals.
- Embeddium compatibility-surface classes that looked unreferenced turned out — verified in bytecode — to be linked by name from the Iris bundled with Demonica; they are pinned by a test instead of deleted. Three never-read private fields were deleted.

### Known issues

- **#422 (purple squares on the loading screen, RX 7900 XTX) is NOT fixed.** Triage continues. This release ships PR #426's upload-slot fix for the first time (it was not in 0.2.5); that addresses a candidate mechanism for vertex/index corruption, not the purple squares themselves. Thanks to the reporter for running the diagnostic builds.
- **#423 (native crash in nvoglv64 on world creation, GTX 1650 Ti) awaits the reporter's re-confirmation on real hardware.** The fix itself shipped in 0.2.5.
- **Darkening from the in-core terrain shadow lookup alone is not established.** The lookup's application counters run, but no shadow-shape darkening has been measured in the presented image. For the pack route, see the Shadows section.
- **HUD caching is not in celtium.** Closed by measurement: in the measured run, 0 of 575 HUD groups were cacheable (0.0%), so the cache's premise did not hold.
- **Sign-text buffering is not implemented.** Its Gate 0 measurement did not show it dominant, so it was not built.
- **Item-frame maps may still have a residual issue where a group closes before the map reaches drawing.** The NPE that came from save-side inconsistency (map color indices beyond vanilla's definitions) measured 270 → 0 after the save was repaired. The celtium-side remainder has its discrimination instrument ready, but no conclusion yet.
