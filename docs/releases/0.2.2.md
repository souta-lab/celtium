# Celtium 0.2.2 — round-15 checkpoint

*Released 2026-11-07 · tag [`v0.2.2`](https://github.com/souta-lab/celtium/releases/tag/v0.2.2) · previous [`v0.2.1`](https://github.com/souta-lab/celtium/releases/tag/v0.2.1)*

*English: [0.2.2 release notes (English)](https://github.com/souta-lab/celtium/blob/main/docs/releases/0.2.2-en.md)*

0.2.1 のホットフィックスに、**round 15 の成果（ウィンドウpollの省略と、mod framebufferのdepth破棄）**を
含めたチェックポイントです。**`-Dceltium.vulkan.validation=true` を付けた環境で、validation layer が無い/到達できない
場合に起動できなかった**問題も修正します。

## 修正

- **validation を要求しても、使えなければ起動を続ける**。これまでは `ValidationBridge.enable` の
  `InvocationTargetException` が「validation support is present but could not be reached」としてデバイス作成を
  8回失敗させ、ゲームが起動しませんでした（テスターの AMD 環境で再現）。
- 起動前に **layer / `VK_EXT_debug_utils` / LWJGL binding** を確認し、使えない場合は
  `[Celtium] CELTIUM_VALIDATION_UNAVAILABLE reason=... (continuing without validation)` を出して続行。
- messenger の作成に失敗した場合も同じ扱い（起動を止めない）。
- 反射呼び出しの `InvocationTargetException` を**原因メッセージ付き**で報告するようにし、次回は
  「layer が無い」「binding が古い」などがそのままログに出ます。

## round 15 の変更

- **ウィンドウpollの省略**: `FrameCoordinator.submitCommands()` が `RECORDED`（バッチ経路でフレームのコマンドバッファに
  残った）または `SKIPPED`（デバイス停止）を返した場合、そのウィンドウの終わりに `celtium$pollCompletedSlots()` を
  呼ばない。キューに何も渡っていないので、pollは前回と同じフェンスを読み直すだけ。確認は次フレームの
  `beginCommands` が行う（遅延であって喪失ではない）。KPI scene で `slotPolls` **20.6 → 1.03/フレーム**、
  `frameFenceWaitMillis` 68 / 55 で新しいストールなし。`WindowPollDecisionTest` が規則を4ケースで固定。
- **mod framebufferのdepth破棄**: modのbloom chainはdepth attachmentを持たないため、そのパスはpairのdepthを
  load/storeする必要がない。`VulkanTerrainPipeline.createChainPairRenderPass` が同じattachment/subpassで
  depthを `CLEAR` / `DONT_CARE` にしたパスを作る（互換規則はformat・sample・referenceのみで、load/storeは含まない）。
  `-Dceltium.vulkan.chainPairDiscardDepth=false` で旧パスに戻せる。`celtium$windowBeginInfo` はCLEAR用の
  clear value（depth 1.0）を渡す（`r15depth-val-amd` の VUID-00902 を解消）。

## 検証

- build: `:celtium-vulkan:test :forge122:packageJar :forge122:validationRemapJar` 成功。
- `scripts/tests` 183 OK、route verifier 259/87 failed=0。
- AMD RX 6400 の leg `r16val2`（validation=true、plain、240 s）: ゲーム起動、
  `CELTIUM_VALIDATION messenger=0x... layer=VK_LAYER_KHRONOS_validation`、validation メッセージ 0。
  fixture は plain scene の較正なし（`UNCALIBRATED_PRESENTED_IMAGE`）だが、**起動失敗ではない**。
- AMD RX 6400 の leg `r17wip`（world、guiScale 3、validation on、240 s）: **PASSED**、
  `CELTIUM_RECORD chain-pair render pass created (depth cleared and discarded)`、
  validation メッセージ **0**（VUID-00902なし）、picture gate PASSED。

## インストール

1. Cleanroom Relauncher（0.7.12-alpha 以降、0.7.14 検証済み / LWJGL 3.4.3 / ゲーム JVM Java 25+）。
2. `celtium-forge-mc1.12.2-0.2.2.jar` を `mods/` に置く（Celeritas は入れない）。
3. validation を使う場合も、layer が無ければ警告を出して通常起動します。

## 既知の課題

0.2.1 と同じ（p99 の pair 外れ、modpack のログ全文/画像比較 pending、葉の mipmap、ATM3 の空、
RLCraft の ordering flush、GTCEu bloom の既定 off）。本リリースは起動修正のみです。
