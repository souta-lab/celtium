## Celtium 0.3.3

現行レンダリングエンジンの最終リリース。対象ビルドは main `85901595`（v0.3.2 タグから 145 commits）。ゲートは着地ツリーでのフルゲート全緑（1,301 tests、failures 0 / errors 0）。jar は `celtium-forge-mc1.12.2-0.3.3.jar` で、SHA-256 は `.sha256` アセットとして同梱する。

このリリースは、現行エンジンを使い続ける人が 0.3.2 以降に着地した修正——とりわけ下記の起動時クラッシュ——を受け取れるようにするためのもの。レンダリングエンジンは Vulkan ネイティブなアーキテクチャとして一から書き直し中であり、このエンジン系列の後続リリースは予定していない。0.3.3 への報告は読むが、修正は 0.3.4 ではなく新エンジン側に着地する（起動自体を妨げる問題は除く）。

### 修正

#### mod 読み込み中のクラッシュ（NVIDIA ドライバ内のアクセス違反）

- ローディング画面の flush は、キャッシュした `VkRenderPassBeginInfo` を再利用する。この構造体がゼロ初期化なしで確保されていたため、`pNext` フィールドに以前のメモリ内容が残り、最初の flush でドライバがゴミを読むことがあった——mod 読み込み中、`nvoglv64.dll` の中でのアクセス違反として、起動のたびに、celtium があるときだけ発生する形で現れた。0.3.2 に対して GTX 1650 Ti 環境から報告があり、報告者のログから追跡した。
- キャッシュする begin info は確保時にゼロ初期化し、`pNext` も明示的に書くよう直した（`calloc` ＋ `pNext = 0` の明示）。修正は、クラッシュの発生箇所として特定された呼び出しそのものに入っている。

#### BSL の黒い楔: pow ガードを既定で有効化

- 0.3.2 では、mod GLSL 変換における小数定数指数の `pow(base, exp)` へのガードを、既定オフ・未検証の状態で出した。その後、出荷済み 0.3.2 jar での検証 leg により、ガード有効時に反太陽コーンの NaN が消え、無効時に再現することを実測したため、既定を反転した。`-Dceltium.vulkan.fractionalPowGuard=false` を明示しない限り有効。

### GlStub の削除（GLSM 移行の完了）

- OpenGL スタブ層を削除した。GL 状態の処理は GLSM 状態機械に一本化され、スタブ経路は残っていない。
- 着地は §6 証拠パック（同一 jar での A/B 提示同一性、旧経路とのカウンタ等価、実 modpack での確認、フレーム時間分布の形（P50/P95/P99））と上記フルゲートを根拠とする。

### その他

- 地形パイプラインは dynamic offset により sampler group 単位で descriptor set を共有するようになり、リージョンごとの set 蓄積の崖が消えた（項目 678 B3）。内部計器、リファクタ、契約チェックの更新も含む。いずれも性能優位は主張しない。
