# Celtium v0.1.3-alpha-rc.3 — combined Windows rendering test

**Experimental test release**, combining the pending flight-visibility fix ([PR #412](https://github.com/souta-lab/celtium/pull/412)) with the mainline model-cache/metadata fixes ([merged PR #413](https://github.com/souta-lab/celtium/pull/413)). Windows correctness and flight performance are **not yet verified**.

## Changes since rc.1

- **Terrain visibility (rc.2):** avoid reusing async visibility lists captured for a different frustum view. Include within-block camera motion, even slight turns, and custom camera offset in the view identity; join current search on changed view.
- **Model capture reconciliation (rc.3):** when a captured display list has no GPU mesh after a world/backend transition, permit exactly one table reconciliation per list and capture version. Show capture/generation diagnostics if still missing.
- **Cleanroom startup warnings (rc.3):** supply a parseable Mixin reference-map resource instead of an empty refmap name, and populate `version.properties` from the same Gradle version as `mcmod.info`.

## Known remaining limitations

`CELTIUM_CAPTURE_MISS` means a GL-less texture was allocated but the original GL upload captured no actual pixel content. We deliberately do **not** synthesize or sample undefined memory. This is not automatically evidence of a missing game texture; render-target allocations can be uninitialized until drawn to. Native GPU copies for offscreen window background chains sometimes use a correctness-preserving readback route, and frame-fence waits include normal synchronization. These need a dedicated profiler and reproducible visual problem before replacement.

Keep **one** Celtium JAR in the instance and retest on Cleanroom 0.7.14-alpha or newer as supported by the launcher.
