# Celtium 0.2.5-rc1

A release candidate on top of 0.2.4: terrain rendering for the Demonica shader pipeline, and a fix for the present-path defects reported on an RX 7900 XTX. This is an RC, published so the fixes can be verified on real hardware; it is not a final release.

## Demonica (shader pack) progress

Verified on the validation fixture (AMD Radeon RX 6400) with a locally built, guard-removed Demonica 0.9.1 and ComplementaryReimagined r5.9.3: shader pipeline creation now passes and terrain renders on Celtium's native Vulkan path (presented-image gate PASSED). Foundations that landed for this:

- Image units: `GL_ARB_shader_image_load_store` advertised honestly, as far as the device backs it (32 per program)
- Multiple render targets: draw buffers / color attachments up to 8 (previously 1)
- Texture-unit answers corrected: 32 per stage, 64 combined, including the pname LWJGL2 actually asks for the combined value
- Demonica's 44-byte extended terrain vertex format (ExtendedChunkVertexType) implemented; all three terrain passes (solid / cutout_mipped / translucent) create pipelines and render

**Limits, stated plainly:**

- **Shadows are not complete yet.** Shadow loading does not yet run on the native path, so with a shader pack enabled the world renders without shadows. This is the next main item of work.
- Some FFP emulation programs are still refused when their uniform block exceeds the device's push-constant limit.
- **A stock Demonica jar will not enable shaders against Celtium as-is:** Demonica's own QuarantineGuard pins the Celeritas jar's hash and disables shaders on a mismatch. The progress above was verified with a locally rebuilt, guard-removed jar.

## Fix: purple squares on world join and present initialization (issue #422)

- Swapchain images are now initialized (cleared to opaque black) at creation. Previously a freshly created image's content was undefined, and the rebuild that happens when joining a world could present undefined regions; on AMD this was reported as purple squares on the loading screen (RX 7900 XTX, VSync enabled).
- The other half of the same report — in-world flickering with VSync on — did not reproduce on local hardware, and auditing the present path found no code defect. It is recorded on issue #422 as an environment/driver-side suspicion. How this RC behaves on the reporter's machine is the final check; please report results on #422.

## Other fixes

- A terrain pipeline creation failure no longer crashes the game through a bug in the failure handler that hid the real reason. Failures are recorded with the pass name and only that pass is skipped.
- The mod compatibility document (docs/mod-compatibility.md) now lists the mods refused at startup as renderer competitors (Gnetum, Custom Loading Screen, SmoothFont, Nothirium, Naughthirium) with the reason for each.

## Measurements

The FPS KPI against Celeritas was not re-measured for this RC, and no performance claim is made over 0.2.4.
