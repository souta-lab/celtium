# Celtium 0.1.4-alpha-rc.8 — raw-write ordering and flush cost

Three changes since rc.7, all of them on the window path that a CPU-bound frame spends most
of its time in.

## The raw-write flush is ordered, not unconditional

A world leg's window flushes were attributed by call site for the first time: of 791,864
flushes, 696,594 came from `applyRawWrites` — a mod copying a framebuffer into a texture it
draws later, about twenty-nine windows a frame — and none of them from a refusal path. The
copy re-fills the mirror image, so it must be ordered against queued work that samples that
texture; it was flushing whether or not anything did.

The flush now asks three queues (the open group, the immediate queue, and the two queues
that hold unrecorded groups for other targets) whether any of them samples the texture.
Recorded draws are already ordered by recording order and need nothing. Measured at the
same machine state: raw-write flushes 696,594 -> 408,904 (-41%), warm frame interval
4.37/4.54 -> 4.13 ms.

The first version of this change missed two of those queues; the one shipped here scans all
three.

## The canonical leg script can boot the clone profiles

`gv_leg.py` now passes `--fetch-missing-libraries`: the cohort and world profiles are clones
whose `minecraft/libraries` is incomplete, so without it the run died in
`ForgeHooksClient.<clinit>` with `NoClassDefFoundError: org/lwjgl/BufferUtils` before any
renderer code ran. A launch failure is not a gate failure and the script should not report
it as one.

## Still open

The tester's black screen. rc.7 fixed a genuine use-after-free (a resized post-chain target
was destroyed while recorded command buffers could still name it), and the crash breadcrumbs
are in the build: launch with `-Dceltium.vulkan.crashBreadcrumbs=true` and a recurrence
prints the last 96 renderer operations. Their last log's fault address was identical in two
runs, so this one is deterministic and the crumbs should name the operation.

World-scene picture acceptance is not re-established in this environment: the calibrated
`celtium-world-accept` instance is missing, so the picture claim for the raw-write change
rests on its ordering argument and the queue scan, not on an image gate.
