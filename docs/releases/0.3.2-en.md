## Celtium 0.3.2

A hotfix for 0.3.1. It is centred on crash fixes; there are no new features. The build is main `692821cd0` (69 commits past the v0.3.1 tag `33989b027`). The gate is the full PC gate on the release tree, all green (1,362 tests, 0 failures / 0 errors, 1 known skip). The jar is `celtium-forge-mc1.12.2-0.3.2.jar`, sha256 `f63ea89ccb56dc7191d0750da137b2868fcb602fb3a7e5feb17202bac71f03d3`.

### Fixes

#### Crash at the flush boundary (descriptor-set use-after-free)

- After an immediate draw group was queued, if the descriptor set for its texture was evicted from the cache (a 64-key limit), the freed set could be bound at flush time and crash inside the driver. The hole was confirmed in the Texture family by walking the code originals; the flush now checks whether the prepared set is still in the cache, and rebuilds it if not (main `8592baec4`).
- An audit confirmed the same hole in the three sibling families — Item, Block and Particle — and the same check-and-rebuild was applied to all three (main `d8acd0657`). The Item family shares the 64-entry limit with the Texture family, so this path was reachable in ordinary use.
- **Honest caveat: this fix has not been demonstrated on a live leg in the form "the eviction happened and the rebuild counter fired".** In the verification leg the eviction interleave never occurred and the counter stayed at 0. The basis for the fix is the code-level proof of the hole, the contract tests (EvictedDescriptorRebuildTest 3/3, SiblingEvictedDescriptorRebuildTest 4/4), and the all-green full gate on the integrated tree. It is not claimed that the crash was reproduced under the failing conditions and then plugged.

#### Loading-splash misalignment (window problem 2)

- Right after launch, the loading screen was drawn frozen at the requested size (1280x720) instead of the window's real size — clipped on the right — and corrected itself partway through loading. `presentLoadingProgress` now aligns the layout dimensions to the swapchain's real extent (main `de6375a54`).
- Caveat: the targeted tests are all green, but no live verification leg has been run yet. The landing alone is not claimed to make the problem disappear.

#### A pow guard for the BSL black wedge (default off)

- As a countermeasure for the black wedge that appears on the anti-sun side with the BSL shader pack, a guard for fractional-constant-exponent `pow(base, exp)` was added to the mod GLSL conversion (main `529ccc3da`). The root cause has been pinned down this far: NaNs arising inside the pack's volumetric-light path are converted to black.
- **This guard is off by default**, and is enabled only with `-Dceltium.vulkan.fractionalPowGuard`.
- **It is not written that BSL is fixed.** The verification leg that measures whether the NaNs inside the cone disappear has not been run yet, and whether this resolves the wedge remains unconfirmed.

#### Twilight Forest shader link failures

- Twilight Forest shaders were failing to link because of `gl_NormalScale` (7 of the 8 failures had this cause). The mod GLSL conversion now lowers it to a `celtium_NormalScale` uniform (main `96e8ee123`).
- Caveat: the acceptance leg (re-measuring the compile census) has not been run yet.

#### Other

- Bloom chain routing fix (main `e6da4ad83`): the routing of terrain passes to the bound target was confirmed to fire, but **the halo band still does not reach the presented image, and bloom is not claimed to be fixed**. The problem lies further downstream and is still under investigation.
- Also included: landings of internal instruments, refactors and performance experiments (the explicit-allocation experiment, which measured no difference; removal of the C1 ±Y shelves; the TickTimings latch fix; removal of dead declaration fields, and others). None of these claims a performance advantage.

### Known residuals (not fixed in this release)

- **Item 699**: a path remains where `IndirectImmediateRuns` holds a descriptor across rebuilds of subsequent groups within the same flush. It is outside the scope of the flush fix above and remains unfixed, as an existing residual common to all four families.
- The BSL black wedge itself (as above: the guard is default-off and unverified).
- VUID-09600 is not resolved (it remains, as before).
