# Celtium 0.2.5-rc2

0.2.5-rc1 の上に、新規ワールド作成時のクラッシュ修正（issue #423）と、影の読み込みのネイティブ化、動的ライト、地形描画まわりの性能作業を載せたリリース候補です。正式版ではなく、実機での確認を広げるための RC です。

## 修正: 新規ワールド作成時のクラッシュ（issue #423、NVIDIA）

- 0.2.4 で報告された、ワールド作成のタイミングで NVIDIA ドライバ（nvoglv64.dll）の中で落ちるクラッシュへの修正です。他の mod がフレームの途中でフレームバッファを作る経路で、Celtium のフレームバッファキャッシュが、作り直し済みのフレームターゲットに対して作られた古いフレームバッファを返し得ました。キャッシュは各エントリが「どのカラー/深度ビューの上に、どのサイズで作られたか」を記録し、一致しないエントリは退役させて作り直すようになりました。
- 併せて2点直しています。フレームターゲットの作り直しが完了できない場合は古いターゲットを使い続ける（従来は作り直しだけが進み、壊れた参照が残り得ました）。ワールド終了時は、破棄されたレンダーパスをキーに持つキャッシュを確実に空にします。
- 正直な現状: 修正はコード監査・単体テスト・CI の全モジュールテストで確認していますが、報告環境（GTX 1650 Ti と大規模 modpack の組み合わせ）は手元にないため、実機での最終確認はできていません。報告者の環境で直っているかが最終判定です。結果を #423 へお寄せください。

## 影の読み込みがネイティブ経路に載りました

- rc1 で「まだネイティブ経路に載っていない」と書いた影パスの読み込みが、Celtium のネイティブ経路で動くようになりました（検証フィクスチャ AMD Radeon RX 6400 での実測: ネイティブ深度コピーの提供 8 回以上、拒否 0）。
- ただし制限は残ります。**画面に影が落ちるところまではまだ届いていません。** 影パスの地形描画が影用のターゲットではなく画面側に落ちる問題が残っており、これが次の主作業です。

## 動的ライト（地形シェーディング時）

- VulkanMod-Next の D13 を取り入れ、地形のシェーディング時に動的ライト（手持ちのトーチ等）を反映する仕組みを Celtium 本体に実装しました（docs/mod-compatibility.md の "Built into Celtium" に明記）。検証フィクスチャでの A/B で、光源まわりの画素が実際に明るくなることを確認しています。

## 性能まわり

- 描画リストの保持（D25）: 地形バッチの組み立てをフレームをまたいで保持し、検証フィクスチャでの計測で地形バッチ時間が静止時 0.312 → 0.228 ms/frame、移動時 0.497 → 0.213 ms/frame になりました。
- 頂点の compact 化（D23）: 既定の頂点形式を 24 バイトにし、頂点あたりのメモリを 25% 削減しました。
- 対 Celeritas の FPS KPI は今回も再計測していません（実 pack での計測系が未構築のため）。性能の優劣の主張はしません。

## その他の修正

- シェーダープログラムの変換で、モダンな in/out 宣言に location を割り当てるようになり、従来は変換の段階で落ちていたプログラムが通るようになりました。
- リリース工程に、配布 jar 内の SPIR-V を再検証するステップを追加しました（工程側の変更で、挙動は変わりません）。

## 引き続きの制限

- 製品版の Demonica jar は、そのままでは Celtium に対してシェーダーを有効化しません（Demonica 自身の QuarantineGuard が Celeritas jar のピンを照合するため）。rc1 の記述のとおりです。
- 影の見た目の完成と KPI 再計測が次の主作業です。
