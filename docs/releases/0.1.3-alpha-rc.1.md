# Celtium 0.1.3-alpha-rc.1 — Windows surface and native-crash investigation build

**Pre-release test build, not Windows-runtime verified.** This release candidate is intended for the external tester Neeyo to retry the minimal Cleanroom 0.7.14-alpha / RTX 3070 instance.

## What changed

- **Win32 Vulkan presentation:** enable the `VK_KHR_win32_surface` instance extension. Create a `VkSurfaceKHR` directly from the SDL-owned HWND and its `GWLP_HINSTANCE` rather than calling `SDL_Vulkan_CreateSurface` on Windows. The 0.1.2-alpha retry log failed to create the surface repeatedly and finally crashed inside `SDL3.dll`.
- **Vulkan diagnostics:** report the actual Vulkan loader/binding error instead of labelling all failures as missing `lwjgl-vulkan`. An exhausted startup retry window now fails with an actionable error instead of silently continuing in a blank GL-less window.
- **Windows immediate-mode GUI:** publish the zero-relative base address of `BufferBuilder` direct buffers, not their `ByteBuffer.position()`-shifted address. Check ranges with overflow-safe subtraction.
- **OpenComputers geometry:** accept `GL_TRIANGLE_FAN` through the GL-less compatibility path; the Vulkan index expander already triangulates fans.
- **Release hygiene:** only reflectively query the loading-screen validation fixture with `-Dceltium.validation=true`.

## Test status and cautions

`./gradlew -p build-1122 :celtium-vulkan:test :forge122:packageJar` passed on the Linux build host. Unit tests cover Win32 extension selection, a positioned direct buffer, fan topology, and nonzero fan first-index capture. **This does not prove the Windows crash is fixed.** The Windows report showed a native fault in SDL3.dll, but the complete native backtrace was not provided. If it crashes again, please attach the corresponding `hs_err_pid*.log` in addition to the Prism client log.

Keep exactly one Celtium JAR in `mods`. Do not install any separately supplied `lwjgl-vulkan` JAR: this build bundles matching Java bindings. Java 8 in the Prism launcher is only used to start the Cleanroom relauncher; Cleanroom itself launches with Java 27 in the reproduced report.
