# Celtium 0.1.4-alpha-rc.3 — single-renderer build

Follow-up to 0.1.4-alpha-rc.2. The renderer now has one mode: the GL-less stub is installed
unconditionally and the real-GL bridge arm is gone. This release also lands the tree
minimisation, the exception-free raw-write path, and the two measured CPU reductions in the
immediate path. Nothing in the renderer's output is intended to change.

## Changes

- **One renderer, no mode switch.** `-Dceltium.vulkan.glless` is removed together with every
  read of it, the bridge-only readbacks and GL queries, the bridge middle-present, and the
  bridge-only classes (`VulkanFrameTarget`, `VulkanFogMirror`). 60 files, +791/-3474.
- **Tree minimisation.** The standalone interop prototype, the JMH suite and its Gradle wiring,
  eight classes nothing in the shipped mod reaches, other-target build scaffolding, and the
  disabled root-project CI workflow are removed. 41 files, +176/-4176; the packaged JAR keeps
  every live class body (entry-for-entry comparison in the PR).
- **Immediate path CPU.** The raw-write refresh no longer throws an `IllegalStateException` per
  frame for wrappers that share a renderer-owned image (it asks a predicate instead), and the
  `gluPerspective` census stops walking the stack after 256 calls instead of 4096.
- **Identity model-view baked nothing.** Pre-transformed groups with an identity model view now
  take the plain copy instead of a per-vertex multiply.
- **Optional diagnostics.** The flush-entry census is opt-in (`-Dceltium.vulkan.flushEntryCensus`)
  instead of running two boxed map merges and a queue scan on every window flush.

## Measured (AMD RX 6400, Linux, Cleanroom Relauncher, GL-less)

| | before rc.3 | rc.3 |
|---|---|---|
| SuperSymmetry world-only warm P50 | 2.96–3.18 ms | **2.50–2.62 ms** |
| ATM3 terrain warm P50 | 4.18–5.28 ms | **4.18 ms** |

Every Celtium refusal marker (draw-array, composite, patch, capture-miss, legacy), validation
message and device-loss event is zero on both packs in the acceptance legs. The renderer is
still slower than Celeritas at the same scene (1.4–1.8x on SuperSymmetry, 3.4x on ATM3) and the
performance goal is not claimed.

## Known issues

- A tester's SuperSymmetry session on rc.2 ended at the loading screen with
  `CELTIUM_VULKAN_DEVICE_LOST` (RADV `GPUVM fault`) and a black screen afterwards. Neither the
  published rc.2 JAR nor this build reproduced it locally at 854x480 or 1920x1080. A device that
  is genuinely lost leaves nothing to present, so the picture stays black; the log line
  `CELTIUM_VULKAN_DEVICE_LOST` is the marker to report. Reproduction details are wanted.
- ATM3 keeps a P95 spike (~19 ms) whose cause is not yet attributed.
