# Celtium 0.2.2 — round-15 checkpoint

*Released 2026-11-07 · tag [`v0.2.2`](https://github.com/souta-lab/celtium/releases/tag/v0.2.2) · previous [`v0.2.1`](https://github.com/souta-lab/celtium/releases/tag/v0.2.1)*

Hotfix on 0.2.1 plus the **round-15 changes (window-poll skip and depth discard for a mod framebuffer)**: a checkpoint
that also fixes the case where **`-Dceltium.vulkan.validation=true` prevented startup** when the validation layer was
missing or unreachable.

## Fixed

- **A requested validation layer no longer blocks startup.** Previously an `InvocationTargetException` from
  `ValidationBridge.enable` surfaced as "validation support is present but could not be reached", failed device creation
  eight times and the game did not start (reproduced on the tester's AMD machine).
- Before creating the instance, Celtium now checks the **layer, `VK_EXT_debug_utils` and the LWJGL binding**. When they
  are unavailable it prints `[Celtium] CELTIUM_VALIDATION_UNAVAILABLE reason=... (continuing without validation)` and
  continues.
- A messenger that cannot be created is treated the same way (startup is not stopped).
- The reflective call now reports the **cause message**, so the next log names "layer not installed" or "binding too old"
  instead of the wrapper.

## Round-15 changes

- **Window-poll skip**: when `FrameCoordinator.submitCommands()` answers `RECORDED` (the batched path kept the segment
  in the frame's command buffer) or `SKIPPED` (stalled device), the window's end does not call
  `celtium$pollCompletedSlots()`. Nothing reached the queue, so the poll would re-read the same fences; the next frame's
  `beginCommands` confirms instead (deferred, not lost). On the KPI scene `slotPolls` went **20.6 → 1.03 a frame** with
  no new fence stall (`frameFenceWaitMillis` 68 / 55). `WindowPollDecisionTest` pins the rule with four cases.
- **Depth discard for a mod framebuffer**: a mod's bloom chain has no depth attachment, so its passes need not load or
  store the pair's depth. `VulkanTerrainPipeline.createChainPairRenderPass` builds the same attachments and subpass with
  depth `CLEAR` / `DONT_CARE` (compatibility compares formats, samples and references, not load/store).
  `-Dceltium.vulkan.chainPairDiscardDepth=false` restores the old pass. `celtium$windowBeginInfo` supplies the clear
  value the CLEAR attachment needs (the `r15depth-val-amd` VUID-00902).

## Install

1. Cleanroom Relauncher (0.7.12-alpha or later, 0.7.14 verified / LWJGL 3.4.3 / game JVM Java 25+).
2. Put `celtium-forge-mc1.12.2-0.2.2.jar` into `mods/` (do not install Celeritas).
3. With validation requested, a missing layer now prints a warning and the game starts normally.
