# Celtium 0.2.2 — validation is a diagnostic, not a startup requirement

*Released 2026-11-07 · tag [`v0.2.2`](https://github.com/souta-lab/celtium/releases/tag/v0.2.2) · previous [`v0.2.1`](https://github.com/souta-lab/celtium/releases/tag/v0.2.1)*

Hotfix on 0.2.1. It fixes the case where **`-Dceltium.vulkan.validation=true` prevented startup** when the validation
layer was missing or unreachable.

## Fixed

- **A requested validation layer no longer blocks startup.** Previously an `InvocationTargetException` from
  `ValidationBridge.enable` surfaced as "validation support is present but could not be reached", failed device creation
  eight times and the game did not start (reproduced on the tester's AMD machine).
- Before creating the instance, Celtium now checks the **layer, `VK_EXT_debug_utils` and the LWJGL binding**. When they
  are unavailable it prints `[Celtium] CELTIUM_VALIDATION_UNAVAILABLE reason=... (continuing without validation)` and
  continues.
- A messenger that cannot be created is treated the same way (startup is not stopped).
- The reflective call now reports the **cause message**, so the next log names "layer not installed" or "binding too old"
  instead of the wrapper.

## Verification

- build: `:celtium-vulkan:test :forge122:packageJar :forge122:validationRemapJar` succeeds.
- `scripts/tests` 183 OK; route verifier 259/87 failed=0.
- AMD RX 6400 leg `r16val2` (validation=true, plain, 240 s): the game starts,
  `CELTIUM_VALIDATION messenger=0x... layer=VK_LAYER_KHRONOS_validation`, zero validation messages. The fixture is
  uncalibrated for the plain scene (`UNCALIBRATED_PRESENTED_IMAGE`), which is not a startup failure.

## Install

1. Cleanroom Relauncher (0.7.12-alpha or later, 0.7.14 verified / LWJGL 3.4.3 / game JVM Java 25+).
2. Put `celtium-forge-mc1.12.2-0.2.2.jar` into `mods/` (do not install Celeritas).
3. With validation requested, a missing layer now prints a warning and the game starts normally.
