# Celtium 0.1.3-alpha-rc.4 — Windows GPU stability A/B test

**Experimental Windows test release. Not Windows-runtime-verified.** This combines the flight visibility and model-cache fixes of rc.3 with the Vulkan presenter stability changes of [PR #416](https://github.com/souta-lab/celtium/pull/416).

## New in RC4

- On Windows, `celtium.vulkan.asyncPresent` now defaults to **false**. Present executes on the game thread as a conservative workaround until Windows/NVIDIA multi-threaded queue submission is validated. Linux keeps its previous default. Explicitly specifying `-Dceltium.vulkan.asyncPresent=true` enables the old path for comparison.
- A failed asynchronous batched submission or fatal presenter result (particularly `VK_ERROR_DEVICE_LOST = -4`) now stops further Vulkan work instead of treating it like a swapchain resize. Unexpected presenter interruption also stops submissions rather than losing the still-in-flight job handle.
- JVM regression tests classify fatal and recoverable results and verify operating-system defaults.

## Known unresolved bugs

**No proof yet that the original GPU loss has been fixed.** Logs [25JrY6n](https://mclo.gs/25JrY6n) and [ntBCI3E](https://mclo.gs/ntBCI3E) both end with `vkQueueSubmit ... VkResult -4` on Windows RTX 3070. The first also crashes in NVIDIA `nvoglv64.dll`; the second occurs with Robotic Parts disabled. The complete `hs_err_pid24484.log` is required for a native stack trace. Tracking [#414](https://github.com/souta-lab/celtium/issues/414).

**Robotic Parts GUI still unsupported:** its radial selection menu uses legacy direct `glBegin(GL_TRIANGLE_FAN)` + `glVertex2f` rather than `glDrawArrays`, and GL-less Celtium does not currently capture those vertices. Tracking [#415](https://github.com/souta-lab/celtium/issues/415).

## Test procedure

1. In a fresh test world, with Robotic Parts disabled and *only one Celtium JAR*, try RC4 with no additional flags and compare uptime against the ~10-second hang reported in ntBCI3E.
2. If stable, rerun with `-Dceltium.vulkan.asyncPresent=true` to establish whether the separate presenter thread is implicated. Compare FPS and any chunk flicker.
3. Test the Robotic Parts radial menu separately; do not equate a missing GUI with GPU device loss. Submit the latest Prism log and `hs_err_pid*.log` if available.

Locally validated: `./gradlew -p build-1122 :common:test :celtium-vulkan:test :forge122:packageJar` on Linux JDK25 with JDK8/21 toolchains; distribution JAR checks. Windows runtime verification is pending.
