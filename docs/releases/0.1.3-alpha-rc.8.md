# Celtium 0.1.3-alpha-rc.8 — experimental Vulkan fixes

This prerelease includes the RC7 test line and subsequent framebuffer and copy-path work. It is intended for testing, including Windows/NVIDIA, and does not certify that the original device loss or the Supersymmetry performance problem is fixed.

## Changes

- Keep live framebuffer images instead of evicting them at an arbitrary eight-image limit; retire images and published descriptors when their owners are deleted.
- Align raw framebuffer identities between drawing and texture publication, handle framebuffer and texture deletion, and validate read/copy rectangles against the actual image extent.
- Correct copy submission ordering and image-layout bookkeeping. The GPU window-copy path fixes the copied rectangle's alpha without a CPU pixel round trip, when the required GPU features are available; the host path remains available when they are not.
- Quarantine deferred submission resources after device loss and preserve explicit `-Dceltium.vulkan.asyncPresent=true` on Windows. The Windows default remains false.
- Includes the flight visibility and model replay work already present in the RC7 lineage.

## Validation and remaining issues

Linux AMD RX 6400 and Intel UHD 630 test fixtures exercise framebuffer retention, both deletion orders, partial copy pixels, alpha, scratch resize and Vulkan synchronization validation. The published JAR (sha256 `72665b41e3040da63bfc0555aded6f8b053babd5b304ec2df5d6c4e7208a1d7d`) passed the world-scene gate on both devices, with the fixture PASSED, `rawFboIdentityProbePassed=true`, `CELTIUM_OPAQUE_COPY_PROBE partial/alpha/resize` PASSED, and no Vulkan validation errors in the run logs. These tests are limited to the exercised scenes and drivers: the distributed map's world scene and the fixture's own cases, on AMD RADV and Intel ANV only. Packaging and its licence content were verified separately; neither is a Windows result.

The first `VK_ERROR_DEVICE_LOST` in the Windows/NVIDIA Supersymmetry report is not conclusively diagnosed or fixed; the prior fence fix prevents a subsequent native crash. Raw framebuffer reattachment, GregTech Unreal Bloom pixel correctness, and Robotic Parts' immediate-mode radial GUI remain incomplete. Modpack FPS and Windows performance have not been measured for RC8. An earlier Linux menu comparison reduced readbacks but showed worse p95 and exceeded the external-load limit, so it is not evidence of a performance improvement.
