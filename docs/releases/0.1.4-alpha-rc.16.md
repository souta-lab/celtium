# Celtium 0.1.4-alpha-rc.16 — a garbage array layer in the pair clear

rc.15 shipped a real defect: the pair clear's reused `VkImageSubresourceRange` was allocated with
`malloc` and only its two counts were set, so `baseMipLevel` and `baseArrayLayer` were whatever the
allocation held. The Khronos validation layer read a garbage `baseArrayLayer` (1163873110) and
reported `VUID-vkCmdClearColorImage-baseArrayLayer-01472` on a plain acceptance leg - the
canonical gate refused rc.15 for it, which is what that gate is for.

The range now sets all four fields. Everything else is rc.15 (model runs skip their pipeline and
descriptor binds when the previous draw was the same run), and the canonical plain gate is
PASSED with the floors enforced and the presented image judged.

rc.15 is withdrawn.
