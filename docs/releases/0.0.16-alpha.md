# Celtium 0.0.16-alpha

対象: **Minecraft 1.12.2 / CleanroomMC 0.7.11-alpha / SDL3・LWJGL 3.4.3 / Java 27**。
0.6.13-alpha（GLFW / LWJGL 3.4.1）は起動時に明示拒否します（SDL3バインディング不在のため）。

## 主な修正

### タイトル画面のパノラマ背景（利用者報告①）

- **症状**: メニュー背景がぼけず、巨大な文字の格子が全面に出る。
- **原因**: メニューはパノラマを256×256に描き、`glCopyTexSubImage2D`（readFbo=0）でその矩形を
  テクスチャへ写してから全画面に拡大する。Celtiumのnative blit経路は「当フレームの描画がまだ届いて
  いない画像」をコピーしてしまい、コーナーに残っていた**前フレームのGUI文字**を取り込んで増幅していた。
- **修正**: window読みのコピーをhost経路（flush → デバイス完了待ち → readback → upload）で提供する。
  読み出しはpresent毎に同一矩形でキャッシュし、7回のコピーでも読み出しは1回。

証拠（AMD RX 6400・同一JAR・leg `menu69` / `menu70`）:

| 経路 | mean | 彩度 | 参照画像との差 |
|---|---|---|---|
| blit（従来） | 105.3 | 0.042 | 65.63% |
| **host（本リリース）** | **112.0** | **0.303** | **43.35%** |

- 画像: `docs/evidence/2026-10-24-v0.0.16-menu.png`（ぼけた風景・ロゴ・ボタン・文字すべて正常）
- 読み出し回数: 756 → 119〜130（leg `menu69` → `menu72`、画像は同一）

### 診断計器の修正（誤った「実測」の訂正）

コピー元のreadbackとテクスチャダンプが `waitForIdle` 無しで読んでおり、**古いフレームの内容を現在として
報告**していた。待機を入れて再測した結果、「コピー元が前フレームの文字」という以前の読みは計器側の
誤りだった（wait付きでは present 1〜122 のすべてで風景 mean 118〜126 / bright 0.0000）。計器は既定off・
境界付きに変更。

## 既知の問題（未修正・明記）

- **性能**: KPIハーネス（AMD RX 6400、world、validation off、warm tick 400–600）で
  **warm p50 2.02–2.08ms / 参照 Celeritas 2.5.0-dev 1.19–1.27ms ＝ 約1.7x**。
  同日午前の測定では同一コード系が 1.56ms / 1.31x だった。affine bakeの無効化
  （`-Dceltium.debug.noAffineBake=true`）でもwindow copy経路の切替でも数値は変わらず、**差の帰属は未決**。
- メニューは1presentあたり最大7回のコピーを行う（読み出しはキャッシュで1回）。**メニューの体感フレーム時間は未測定**。
- native blit経路のwindow読みは画像/順序が一致せず、既定で回避している（`-Dceltium.vulkan.windowCopyBlit=true` で旧経路）。
- ②エンドポータル内部の見え方、④ステンドグラスのちらつき、⑤サイン文字の残像は未修正。
- RLCraft 2.9.3 の現行プロファイルは CleanroomMC 0.6.13（別ホスト世代）のため、本ビルドでは起動できない。

## フラグ

- `-Dceltium.vulkan.windowCopyBlit=true` … window読みコピーをblit経路へ（既定false。メニュー背景が壊れる既知不具合あり）
- `-Dceltium.vulkan.cacheCopySource=false` … コピー元readbackのpresentキャッシュを無効化
- `-Dceltium.debug.noAffineBake=true` … 計測用（affine bakeを実行時に無効化）
