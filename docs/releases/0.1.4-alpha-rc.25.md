# Celtium 0.1.4-alpha-rc.25 — a device loss now leaves a file to attach

The tester's black screen is a device loss the renderer cannot recover from, and the only trace was one line in a
large log. When the first loss happens the breadcrumb dump now also writes `celtium-device-lost.log` beside the game
(in the instance's `minecraft/` directory), with the trigger operation and the whole ring of renderer operations that
led to it, and names the path in the log. A report of "still black" then arrives with the artifact that says which
operation was in flight.

Also carries rc.24: the retire queue no longer drains while a command buffer is recording, and the post chain's
replaced main framebuffer is retired instead of destroyed (`VUID-vkEndCommandBuffer-commandBuffer-00059` named both),
plus `-Dceltium.vulkan.retireRecordingGuard=false` for measurement.

Canonical plain gate: PASSED with floors enforced and the presented image judged.
