# Celtium 0.1.4-alpha-rc.15 — the model runs stop re-binding

A world frame's immediate work is not the immediate group path: it is about a hundred model runs
a frame, each drawn as one multi-draw-indirect call over the bindless texture array. Every run
bound its pipeline, its descriptor set, its vertex and index buffers and then drew; consecutive
runs almost always share the first two, because there is one array set and one pipeline per
material.

Those two binds are now skipped when the previous draw in the same segment was a model run with
the same pipeline and set. The cache is invalidated at the one place that can see a change: the
group loop clears it for every group whose modelRun is null, so any non-model draw in between
makes the next run bind again. The projection/fog push, the buffer binds and the indirect draw are
always emitted.

Measured on the Susy world leg: warm P50 2.54 ms, no device loss, no validation messages, and the
canonical plain gate is PASSED with the floors enforced and the presented image judged.

The rest is rc.14 (always-on crash breadcrumbs, reused window structures, coalesced raw writes).

## Also in this build

The opaque material ordering keeps its wider predicate (unlit item groups are reorderable by the
same depth/blend argument as lit ones) but stays off: with that predicate only 8 of about 112
groups qualify, so it cannot pay for itself yet.
