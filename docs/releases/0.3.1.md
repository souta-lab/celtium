## Celtium 0.3.1

0.3.0 の保守リリース（同日）。クラッシュ2件と Demonica のメニュー崩壊を直し、0.3.0 の後に着地した性能作業を含む。合体フルゲートは common 119 / celtium-vulkan 1,108 / forge122 50 の **1,277 件、失敗・エラー 0**（既知の skip 1件）。

### 見た目で分かること

- **Demonica 併用時のメニューが正常に描かれるようになった。** celtium 0.3.0 + Demonica では GUI が崩壊していた（文字が白いブロックになる、メニュー背景が真っ黒、テクスチャ欠落）。原因3件は全て修正済み（下記）。証明実走では、タイトルメニュー・ロゴ・ボタン・設定画面が Demonica 併用で正しく描かれることを確認した。
- **エンチャント台を置いても落ちなくなった。** 同じクラッシュは、互換経路で display list を再生する全ての TESR（エンチャント台の本、チェスト、ベッド、バナー、頭蓋骨）で起きていた。
- **Alt-Tab・最小化・リサイズで落ちなくなった。** ウィンドウ表面が一時的に 0x0 サイズを返す状態は、致命的な swapchain 失敗ではなく「待つ」状態として扱うようになった。

### Demonica GUI 崩壊: 重なった3つの原因

崩壊は1つのバグではなかった。Demonica 同梱の GLSM 層がゲームと celtium の間に挟まる同じ GUI 経路に、3つの独立した欠陥が重なっていた。

- **(a) テクスチャ無効バッチが捨てられていた。** GLSM のテクスチャ付き固定機能プログラムが束縛された状態で position のみのバッチが届くと、属性の対応付けに失敗してバッチが拒否されていた。テクスチャ無効バッチは、束縛中のテクスチャ付きプログラムの下でも内蔵パイプラインで描くようになった。
- **(b) テクスチャ付き GUI 描画が届いていなかった。** GLSM は BufferBuilder の描画を取り消し、VAO 記述のインデックス描画として自前レンダラへ回す。celtium の stub はそのレイアウトを読めず、テクスチャ付き描画（メニュー背景・ロゴ・ボタン）がバックエンドへ届いていなかった。stub が VAO 記述のレイアウトをデコードして描画を通すようになった。証明実走では描画 census が呼び出し census と完全一致し、拒否は 0。
- **(c) 線幅の答えが、リンクできないプログラムを武装させていた。** stub が実デバイスと矛盾する線幅範囲を答えたため、GLSM がジオメトリステージの太線エミュレーションを有効化し、そのプログラムは celtium の2ステージ lowering ではリンクできず、ワールド内でクラッシュしていた。stub はデバイスの実最大線幅を答えるようになり、エミュレーション自体が武装しなくなった。

あわせて、Demonica の OpenGL プロファイルが互換プロファイルに解決されて celtium の正直な GL 3.0.0 下限に引っかかり Demonica が止まる場合に、変更すべき設定（`config/demonica-options.json` の `advanced.opengl_profile` = `CORE`）を名指しするヒント行をログに出すようになった。

### 修正したクラッシュ

- **TESR の MemoryStack 枯渇（0.3.0 の回帰）。** immediate flush が flush 全体で1つの MemoryStack フレームを保持し、グループごとの一時確保が無制限に積み上がっていたため、タイルエンティティを置く（エンチャント台で十分だった）とスタックが枯渇してクラッシュしていた。グループごとのスタックスコープを復元した（スタック消費はグループ数に対して定数。スタックを大きくしたのではない）。あわせて、それを守る契約チェックを CI に再配線した（回帰が入ったときに削除されていたもの）。
- **swapchain 0x0 クラッシュ。** ウィンドウ表面が 0x0 の extent を固定する状態（最小化・リサイズ中・Alt-Tab）で swapchain 生成が拒否され、再試行の末に約2秒で致命的クラッシュへエスカレーションしていた。0x0 の固定は「表面サイズ待ち」として分類し、実サイズが来るまで待つようになった。構造的な拒否（使用可能な形式がない、転送・合成の対応がない）は従来どおり拒否する。
- あわせて、パック地形の実行をホスト側の状態スナップショット／復元ガードで括るようになり、パックのプログラムが後続パスへ GL 状態を漏らさなくなった。

### 性能

- **リージョンオフセットを binding-5 SSBO 経由に。** 地形のリージョンオフセットを `firstInstance` で引く SSBO で届ける形にし、描画ごとの descriptor 作業を置き換えた（パスあたり descriptor bind は1回）。着地時の実測（agera 定常窓）で record-bind コストが約4分の1低下。
- **グローバル頂点／インデックスアリーナ。** 地形ジオメトリを共有のグローバルアリーナへ入れ、パス内では indirect draw を連鎖させる形にした（セクションごとのバッファは廃止）。着地時の実測で、飛行場面のフレームあたり描画記録コストが約1桁低下。
- **グラフィックスパイプラインが実行のたびに再生成されなくなった。** シェーダパック使用時、パイプラインキャッシュのキーに含まれるブレンド状態オブジェクトのハッシュが生成のたびに変わり、キャッシュが永久にミスして `vkCreateGraphicsPipelines` が実行のたびに走っていた。ブレンド状態に内容ベースの等価性を入れた。実測（Complementary の石柱場面、PC・RX 6400）: パイプライン生成は leg あたり 390 回（フレームあたり約4.48回）→ **6 回**。

本版では性能の全面的な優位は主張しない。内蔵 GPU の飛行場面の差は引き続き作業中。

### 既知の問題（誇張しないための明記）

- **BSL の黒い楔は本版では直っていない。** 影対応の BSL パイプラインが構築された状態で、提示フレームに未描画の円錐が出ることがある。celtium 側の観測点は全て、壊れる構成と健全な構成で同一であることを確認済みで、残る locus はドライバ側の実行。GPU フレームキャプチャによる調査を継続している。「直った」とは書かない。
- **VUID-09600 は解消していない。** Complementary の実走で 10 件の残存があり、0.3.0 から変わっていない。
- 同じ報告者からの Xaero ミニマップ報告は再現・切り分けの途中で、本版では肯定も否定も書かない。
