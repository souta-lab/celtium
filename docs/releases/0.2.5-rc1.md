# Celtium 0.2.5-rc1

0.2.4 の上に、Demonica 対応の地形描画と、RX 7900 XTX で報告された present 系の不具合修正を載せたリリース候補です。正式版ではなく、実機での確認を広げるための RC です。

## Demonica（シェーダーパック）対応の進捗

ガードを外したローカルビルドの Demonica 0.9.1 と ComplementaryReimagined r5.9.3 を使った検証（AMD Radeon RX 6400、検証フィクスチャ）で、シェーダーパイプラインの生成が通り、地形が Celtium のネイティブ Vulkan 経路で描画されるところまで進みました（presented-image ゲート PASSED）。土台として入ったもの:

- イメージ units: `GL_ARB_shader_image_load_store` をデバイスの裏付けがある範囲で正直に広告（プログラムあたり 32）
- マルチレンダーターゲット: draw buffers / color attachments を最大 8 まで（従来は 1）
- テクスチャ units の回答是正: per-stage 32、combined 64（LWJGL2 が combined を尋ねる pname にも正しく回答）
- Demonica の 44 バイト拡張頂点フォーマット（ExtendedChunkVertexType）を実装し、地形 3 パス（solid / cutout_mipped / translucent）がパイプラインを生成して描画

**制限（正直な現状）:**

- **影はまだ完成していません。** 影パスの読み込みがまだネイティブ経路に載っておらず、シェーダーパック有効時は影なしの描画になります。これが次の主作業です。
- FFP エミュレーションの一部プログラムは、uniform block がデバイスの push-constant 上限を超える場合に引き続き拒否されます。
- **製品版の Demonica jar は、そのままでは Celtium に対してシェーダーを有効化しません。** Demonica 自身の QuarantineGuard が Celeritas jar のピンを照合し、不一致だとシェーダーを止めるためです。今回の進捗はガードを外したローカルビルドでの検証結果です。

## 修正: ワールド参加時の紫ブロックと present 初期化（issue #422）

- スワップチェーン画像を生成時に初期化（不透明黒でクリア）するようにしました。従来は生成直後の画像内容が未定義で、ワールド参加時に走る再構築の直後に未定義領域が画面へ出ることがあり、AMD では紫色のブロックとして報告されていました（RX 7900 XTX、VSync 有効時）。
- 同じ報告の「ワールド内で VSync 有効時にチラつく」症状は、ローカル hardware では再現せず、present 経路のコード監査でも欠陥は見つかりませんでした。ドライバ側の疑いとして issue #422 に記録してあります。この RC が報告者の実機でどうなるかが最終確認になります。結果を #422 へお寄せください。

## その他の修正

- 地形パイプラインの生成に失敗したとき、失敗処理側のバグでゲームごと落ちて本当の失敗理由が隠れる問題を修正。失敗はパス名つきで記録され、そのパスだけがスキップされます。
- mod 互換性ドキュメント（docs/mod-compatibility.md）に、起動時に競合として拒否する mod（Gnetum、Custom Loading Screen、SmoothFont、Nothirium、Naughthirium）とその理由を明記しました。

## 計測について

この RC では FPS KPI（対 Celeritas）の再計測は行っていません。0.2.4 からの性能面の主張はありません。
