# Celtium 0.1.4-alpha-rc.11 — coalesced raw writes

The raw-write flush was the largest window source left: about twenty-seven windows a frame on
the Susy world scene. Each one existed for ordering - a mod copies a framebuffer into a texture
while queued groups still sample the old content, so the queued groups must be recorded before
the copy. A mod's bloom copies several framebuffers into textures before drawing any of them, so
the old code paid one window per copy.

The copy is now recorded as a *pending* raw write when it is ordered against queued work, and
the copies are written after the queued groups are in the command buffer: at the next window
flush, at the frame boundary, and before any batch that could sample them (a batch accepted
while copies are pending flushes the queue first, so copies always precede it in recording
order). The serial is marked applied when the copy is queued; a later write to the same texture
replaces the entry, and the copy reads the texture's newest captured content either way.

Measured on the Susy world scene, two A/B pairs in both run orders:

| | coalesced | off |
|---|---|---|
| raw-write flushes | 17.3-17.5 per frame | 26.7-28.0 per frame |
| warm P50 | 3.49 ms | 3.96-4.09 ms |

The canonical plain gate (guiScale=3 options, floors enforced, presented image judged) is
**PASSED** with the flag on: `verdict=PASSED`, `sceneCalibrationKeyMatches=true`,
`sceneGateFloorsEnforced=true`, AMD RX 6400.

Coalescing is on by default; `-Dceltium.vulkan.coalesceRawWrites=false` restores the old path.
