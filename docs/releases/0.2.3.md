# Celtium 0.2.3 — マルチ OS 検証リリース

*Released 2026-11-16 · tag [`v0.2.3`](https://github.com/souta-lab/celtium/releases/tag/v0.2.3) · previous [`v0.2.2`](https://github.com/souta-lab/celtium/releases/tag/v0.2.2)*

0.2.2-rc1 は、読み取り範囲ガードの Linux 前提が原因だった Windows 固有の不具合を修正した。本リリースは
その仕上げとして、リポジトリ全体を対象に OS 固有の前提を監査し、見つかった欠陥を修正したうえで、CI で
テストスイートを Linux に加えて Windows と macOS でも実行するようにした。同種の前提は、今後は出荷
される前にビルドで落ちる。

## 「マルチ OS 検証済み」の意味

本リリースでこの言葉が意味するのは、正確に次のことだけである。`celtium-vulkan` のテストスイート全体
（94 suites / 462 tests）と、OS 非依存なリポジトリ検査（`check_agent_docs.py`、
`instrument-index.py --check`）が、3 つの OS の CI ランナー（Ubuntu、Windows `windows-latest`、
macOS `macos-latest`）すべてで同一の結果で合格すること。同ーワークフロー実行で確認した
（[run 43877915571](https://github.com/souta-lab/celtium/actions/runs/43877915571)）。実機でゲーム
そのものを動かしたという意味ではない（Known limits 参照）。

## Fixed

- **テストビルドが Linux ホストを前提にしなくなった。** `celtium-vulkan` のテスト実行時依存は LWJGL
  natives の classifier を `natives-linux` に固定していたため、Windows や macOS のホストではテスト JVM
  が Linux 用 `.so` を展開し、shaderc バインドの初期化に失敗して、スイート自体が Linux 以外で実行
  できなかった。classifier はホストの OS とアーキテクチャに従うようになった。
- **シェーダコンパイラが Windows と現行インストールで見つかるようになった。** PATH 探索は裸の
  プログラム名しか試しておらず、Windows の `.exe` には決して一致しなかった。また候補は改名後の
  `glslang` を知らず、現行の Khronos 製 Windows リリースは `glslang.exe` しか含まない。探索は
  Windows で `.exe` 形式も試し、`glslang` は全 OS で候補になり、見つからない場合のメッセージは
  Debian/Ubuntu に加えて macOS と Windows の導入経路も示す。
- **読み取り範囲ガードが macOS に対応した。** 0.2.2-rc1 の修正の背後にあるガードには Linux
  （`/proc/self/maps`）と Windows（`VirtualQuery`）のプロバイダしかなく、macOS では owned buffer の
  公開で覆われないクライアントメモリからの描画がすべて拒否されていた。Windows の不具合と同じ種別の
  欠陥である。macOS プロバイダは `mach_vm_region`（FFM）で VM 領域を歩行し、他のプロバイダと同じ
  テスト可能な継ぎ目を持つ。この欠陥は新しい CI leg が出荷前に検出したもので、初回実行は Windows が
  green、macOS はクライアント配列のテストちょうど 3 件で red だった。
- 監査の残りの所見は、安全に劣化する設計どおりのもの（例：上記 3 OS 以外ではガードは既定で拒否する）
  か、確認済みで問題なしのいずれかに分類した。分類の全体は変更履歴とともに記録している。

## CI

- 新しい `vulkan-multi-os` マトリクスジョブ（Windows、macOS）が `:celtium-vulkan:test` と OS 非依存な
  検査スクリプトを実行し、glslang 16.6.0 を Khronos 公式リリースアーカイブから固定して導入する。
  両 leg はシェーダコンパイラの解決をビルド自身の PATH 探索に意図的に委ねており、Windows の `.exe`
  探索そのものがテスト対象になっている。既存の Ubuntu ジョブは不変で、Forge のパッケージング
  （`:forge122:packageJar`）は Ubuntu leg のままである。出荷する jar はプラットフォーム非依存である。

## Known limits

- Windows と macOS の実機でのゲーム内確認はまだ。実インストール環境での実際の描画（Windows の
  EfficientEntities、macOS の MoltenVK など）、フレーム時間への影響、ゲーム自身の JVM での FFM
  バインドは実機未確認。CI leg はホスト型ランナー上のテスト JVM でバインドを動かすところまでであり、
  出荷されうる不具合の範囲を狭めるが、ゼロにはしない。
