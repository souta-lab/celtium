# Celtium 0.1.4-alpha-rc.13 — the window's own fixed costs

The pass split put a world frame's flush at 0.8-0.9 ms p50 against 0.2 ms of draw work: the rest
was the per-window machinery, about thirty windows a frame. This release removes part of it.

## Reused window structures

The window's `VkRenderPassBeginInfo` and its render area were allocated and filled per window,
for contents that change only when the render pass, framebuffer or extent do. They are now built
once per that combination and reused; the pair clear keeps its range, colour and depth
structures for the pair's lifetime, with the values still read from GL every clear.

Measured on the Susy world leg: `winRecord` 0.6 -> 0.5 ms p50, warm P50 2.61 ms, no device loss,
no validation messages. The canonical plain gate (guiScale=3 options, floors enforced, presented
image judged) is PASSED.

The first version of this change keyed the cache with a hash and lost the device on a loaded
world: two different framebuffers hashed to the same key and a pass was recorded against the
wrong one. The shipped version compares the four fields exactly.

## What the frame split says

Susy world leg, pass split, p50 ms: frame 1.9, flush 0.8, of which winRecord 0.5 (draws 0.2,
begin-pass 0.1), winBarrier 0.1, winSubmit 0.1; terrain 0.1; sky 0.1. The remaining gap to the
reference is the thirty windows' fixed cost plus the per-batch Java work, not the drawing.

## Still open

FPS parity: paired measurements on a cool machine read Susy about 1.46x and ATM3 about 1.45x.
Black-screen report: the breadcrumbs are still opt-in (`-Dceltium.vulkan.crashBreadcrumbs=true`).
