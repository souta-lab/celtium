## Celtium 0.3.0

0.2.5 から 387 コミット（着地 172 件）、380 ファイル、+34,356 / −8,455 行の変更をまとめた版。内訳は、Celeritas からの GL 切り離し3波（PR #426–#428）、2026-11-21 の総力キャンペーン（10レーンのコード監査で挙がった約87件の所見を全て切り分けて処分）、シェーダパック経路の内蔵パイプライン化、そして報告者から寄せられた問題への対応。目玉は2つ。シェーダパックの地形が、色を失わずに提示画像まで届くようになったこと（「影とシェーダパック」の節）。そして動的光源の利得を実測で示せたこと。成立していないものは、最後の「既知の問題・未成立事項」に正直に明記する。テストスイートは common 119 / celtium-vulkan 1,078 / forge122 50（合体フルゲート、失敗・エラー 0）まで育った。

### 影とシェーダパック: 地形の色が提示まで届くようになった

シェーダパック（Complementary Shaders / BSL）の gbuffers 地形プログラムは、GlStub を経由せず celtium 内蔵のパイプラインで翻訳され、描画される。今回、その先で起きていた「描いた色が提示に届かない」問題を潰した。

- **実測した提示の変化。** Complementary を、PC（RX 6400）の再構築した無垢な石柱シーン（石柱5本と床だけの場面）で実走した。修正前は、霧の中にテクスチャの無い暗いシルエットとして石柱と床が見えるだけだった。修正後の提示画像では、石柱に石肌のテクスチャと面ごとの方向性の明暗が乗り、床の模様が地平線まで続き、空にはパックの雲が出ている。描画した地形の色と陰影が、提示まで届くようになった。
- **根因。** deferred の出力が、後段の水面パス（gbuffers_water）に奪われていた。深度を持たない deferred1 の公開先を、深度付きの水面パスが再利用できず自前のペアを確保して公開を上書きし、フレームごとのクリアで deferred の出力を消していた。あわせて、色の受け渡し（handoff）の対象が広すぎると、前フレームの最終画像を地形へ複写して白飛びする問題もあった。
- **修正。** 空のパスが公開先を壊さないよう幾何の無いパスを早期に返す、MRT と深度付きウィンドウで深度を保持する変種パスを使う、受け渡しの元を「今フレーム内に実際に書かれたペア」に限定する、の3点を入れた。修正のフルゲートは 1,235 件全通過（失敗・エラー 0）。
- あわせて、提示画像が単色の虚空になる問題（mod プログラムへの pre-transform の誤適用）の修正、地形カラーの公開経路の修正が入っている。検証エラーのうち COLOR 形の 00344 / 00900 は実測で 20 件から 0 件になった。09600 は深度形を処分したが、Complementary の上記実走では 10 件が残っている（解消とは書かない）。
- **まだ主張しないこと。** 床に落ちる影の形そのものの検証（証明レッグ）は着地後に回すため、本版では「影の形が出た」とは書かない。今回実測したのは、テクスチャと面の陰影が提示に届くところまで。BSL はこの修正での実走をまだ行っておらず、BSL が真っ黒になる別件が残る可能性がある。

### 動的光源（Item 430）: 利得を実測

- 動的光源が地形に効かなかった根因（カメラ減算の二重適用。u_RegionOffset が origin − camera を渡し、シェーダ側が再度 camera を引いていたため距離が膨らみ、光源の raise が恒常的にゼロだった）を修正。
- **利得を実測した。** 暗い場面（koenigsegg-agera、Intel HD Graphics 620、松明アイテムを露出させた fixture 場面、OFF/ON 各1回）で、床中心の領域の平均輝度が OFF 28.62 → ON 52.28（+23.65）。対照領域は空 +0.06、石台の上面 +0.31、床の左端 +2.31 とほぼ不変で、全画面平均は 29.99 → 35.52。光源の近くの床だけが持ち上がり、遠方は持ち上がらない — 光の減衰として正しい形。計装でも、ON では光源の出現と同時に funnel の初回 raise が発火し、OFF では hit・raise ともにゼロだった。
- これは HD 620 での機能実走の数字で、RX 6400 での性能の物差しではない。
- あわせて、動的光源の集計（FUNNEL_SUMMARY）がワールド退出時に印字されるようになった。従来は計数器に呼び出し箇所自体が無く、JVM 終了フック頼みでハーネスのログに残らなかった。

### 報告を受けた問題への対応

- **#422（Karnatour、RX 7900 XTX）: 4症状すべての机上根因に手を入れ、本版に入れた。** (1) 読み込み画面の紫タイルは RDNA3 の表面圧縮（DCC）の不整合が主候補で、提示経路の既定を転送専用に切り替え、提示まわりのバリアを補完した。(2) ワールドが +y200 ずれて描かれる・葉が空中に残る症状は、地形 uniform の単一バッファがフレーム内書き込みで上書きされる競合が原因で、スロット別のリングに分離した。(3) 黒い水・葉の欠けは、地形フレーム予算の上限（400万頂点）に報告者のログ上で到達しバッチが落とされていたため、既定の上限を撤廃した（明示指定は従来どおり有効）。フルゲートは全通過。**ただし報告者の RX 7900 XTX 実機での確認はまだで、「実機で直った」とは書かない。** 本版での再確認をお願いする立場。
- **#423（밥다섯、GTX 1650 Ti、ワールド作成時に nvoglv64 でネイティブクラッシュ）:** 修正自体は 0.2.5 で出荷済み。本版でも報告者の実機再確認待ちのまま。
- **#424（yakan12、Efficient Entities でバッチ化されたエンティティモデルが描かれない）:** 元の機構への対処は 0.2.5 で入れた。残件だったマッピング再読込の寿命上限（64回）の撤廃が本版で初出荷になる。本版での再テストをお願いする立場で、「直った」とは書かない。
- **#425（밥다섯、レンダラ再読み込みの teardown 中に device lost で落ちる）:** 報告の切り分けは報告者のログ待ちが続いているが、製品側の防御的な堅牢化を本版に入れた。SimpleWorldRenderer の再構築時の破棄を例外で中断しない形にし、GPU バックエンドの破棄は確定済み資源の解放を段階に分けて、途中で失敗しても登録解除は必ず行うようにした。
- **Item 529（밥다섯、レンダラ再読み込み後に vkCreateDevice が VkResult -3 で失敗し hard に落ちる）:** デバイス生成に失敗した場合のエラーに、結果コード・デバイス名・有効化した拡張と機能・同一プロセス内で直前に起きたデバイス喪失の記録を同梱するようにした。あわせて、失敗がそのままクラッシュに化ける経路の堅牢化と、deferred batch のデバイス喪失への帰属計器（I1–I7）が入っている。

### 修正（クラッシュ・ハング・寿命）

- 描画セクションの遮蔽（occlusion）探索で例外が出たとき、inFlight フラグが残って毎フレーム画面が固まり得た問題。
- RenderListManager の inFlight リークと、teardown の再試行契約（shutdown の no-op 契約と destroy の段階分離）。
- swapchain の outOfDate 判定に消費者がおらず、取得がハングし得た問題。取得が繰り返し失敗したときは失敗を上げて上位へ返すようにした。
- swapchain の生成が連続して失敗し続ける場合に、無言の黒画面のまま固まるのではなく、上限到達でクラッシュレポートを出すようになった。
- retire queue が旧デバイスを掴んだまま破棄し得た問題を、所有デバイスでタグ付けして是正。遅延クリーンアップの破棄処理が後継デバイス上で走る経路も塞いだ。VulkanContext.delete の flush/drain の device-lost 出口でも pipeline cache と retire を落とすよう統一。
- デバイス喪失で退役した旧デバイス側の GPU 資源が二重に解放され、ネイティブクラッシュし得た問題。デバイスを実際に持たない Vulkan コンテキストの二重破棄も是正。
- コマンドバッファの解放時に、まだ生きている提出を指すフェンスの解放を保留するように。キュー競合で同一フェンスの待機が繰り返され応答が止まり得た問題も是正。
- テクスチャの deferred batch を、staging リング再利用・イメージ再生成・delete の前に提出するよう統一。
- アップロード経路の deferred lifecycle 会計（失敗時と teardown 時）と arena 成長ガード。
- レンダラの再読み込み時の teardown が失敗しても、例外を記録して新しいレンダラの生成を続行するようになった（#425 の報告を受けた堅牢化）。
- 設定ファイルが空・空白・null の場合や quality が null の場合に、設定が読み取り専用の既定値に固定され保存できなくなる問題。
- SimpleWorldRenderer の再構築 dedup 集合の競合を是正（レンダースレッド所有に限定）。

### 修正（描画・表示）

- 負の Z 座標で上下の明るさが入れ替わり得た、LightCache の pack キー衝突（vanilla の BlockPos.toLong と同一レイアウトに是正）。
- チェーンペアのカラーアタッチメントのレイアウト公開が外れ、検証エラー（00344 / 00900）が出ていた問題（実測で 20 件 → 0 件）。深度テクスチャをカラーターゲットとして使ったときの検証エラー（09600 の深度形）も処分。
- 遠方の葉ブロックが透けて見える問題（葉の描画品質設定が透過処理に届いていなかった）。
- 頂点法線の計算が、設定クラスの読み違いで常に素通りになっていた問題。
- 霧の色の計算で、霧色の緑成分が欠けていた問題。
- 雲の色・明るさが、雲描画の色公開が欠けていて常に白になっていた問題。
- フォントアトラスが世代をまたいで名前を使い回し、文字化けの温床になっていた問題。
- スポーンポータルのアニメーションが本来の紫色にならなかった問題。
- 統合型 GPU 環境で、描画範囲の頂点インデックスが 32 ビット幅にならず描画が崩れる問題。
- 額縁の地図が描画されない問題の一因（DynamicTexture の名前解決の不整合）。残件は「既知の問題」参照。
- 地形の記録経路: フォールバック時のパス状態復元、bound target のペア一括取得、merge run の bind 順序、同一イメージへの depth コピー拒否。

### 修正（mod プログラム・GL 互換層）

- push 経路の uniform を prepare 時に凍結（描画中の再利用で化ける問題）。ステージ分類を glCreateShader 基準にし、varying 検証と uniform 初期化子の持ち運びを追加。uniform location の名前ハッシュ衝突は上書きせず数える。抑制されていた mod プログラム報告を集約して出す。
- mod プログラムのリンク成否（LINK_STATUS / VALIDATE_STATUS）と info log が、実際のリンク結果に基づいて返るようになった（LWJGL2 / LWJGL3 の両経路）。従来は無条件に成功を返していたため、リンクに失敗したプログラムが無音で欠けることがあった。
- mod シェーダの翻訳で、コメントの字句解析が実コードを消してしまう問題（uniform が interface から消える）と、#define 本体から宣言を誤って抽出する問題を修正。texture1DProj / texture3DProj の変換漏れも埋めた。宣言抽出はソース内の条件分岐（#ifdef）にも追随するようになった。なお sampler2DShadow 等の shadow サンプラ型は、実パック（Complementary / BSL が使用）との互換のため拒否せず通す形に決着している。
- sampler が上限外のテクスチャユニットを名指すと unit 0 のテクスチャで無音に描画していた問題を、名前つきの拒否に変更。シェーダコンパイル失敗のログにステージ（vertex / fragment）が残るようになり、unsupported の理由も付記される。
- mod が使う ARB/EXT サフィックス付きの GL エントリポイント（FBO・VBO・シェーダオブジェクト・query・copy-image 系）が stub に無く、未知シンボルとして 0 を返していた問題を修正（機能エイリアス39件＋noop パリティ37件）。0 が返ると呼び出し側がデフォルトフレームバッファと誤読する無音誤動作の型だった。
- lightmap の ID 供給が失敗しても未インストールと区別がつかず無音だった問題に、失敗の記録（回数と最初の失敗原因）を追加。
- LWJGL サービスの初期化時に GL を呼んでクラスが JVM の寿命いっぱい死ぬ問題を遅延ホルダで是正。劣化した LWJGL サービスが静的単例に凍結される問題と、デバイス引数を無視する共有 pipeline cache を是正。
- mixin フック名を MCP/SRG 両形式で書く是正群。本番環境で死んでいたフックが復活する。ChunkEntityMembershipMixin の SRG 対象取り違えと RenderItemMixin の死名も是正。@Unique メンバーの可視性を全 mixin で検査する回帰テストを新設（VanillaFix 併用時の起動不能の再発防止）。
- mod プログラムの prepare メモを SPIR-V の同一性でキーするようになり、リソースリロード時にアイテムメッシュのキャッシュが RenderItem のコールバックから確実に消えるようになった。リロードをまたいで古いプログラムやメッシュが残る経路を塞いだ。
- 大きすぎる mod プログラムの uniform block を uniform buffer 経由にルーティングする経路を追加。standalone で確保されたテクスチャを mod サンプラ向けに実体化する処理（Item 537）も入った。
- mod が名前で書いたフィールドが消えていて、mod の初期化が落ちる互換事故（Demonica）を是正。該当の static は実行時値と同期する互換サーフェスとして復活させた。今後、mod が書く static の削除は互換事故として扱う。
- ブロック描画を BlockRendererDispatcher 経由にルーティングし直した（Item 490、上流 Celeritas の高速レンダラ変更の移植）。dispatcher を差し替える mod との互換が回復する。
- 報告スレッド由来の描画 API の穴埋め（glGenBuffers / glBindBuffer / glBufferData など）と、glCopyImageSubData のテクスチャレベル間コピーの実装。

### 互換性

- **VanillaFix との併用を確認**（起動クラッシュを切り分けて解消。テクスチャアトラスの可視性ゲートを HEAD 注入に作り替えて同居可能にした）。
- **FoamFix 0.10.15 との併用を確認**（RX 6400、fixture で実走し提示画像は健全）。ただし FoamFix の高速アニメーション経路はこの構成では発動しない — Cleanroom の LWJGL2 層が OpenGL 4.3 / ARB_copy_image の能力を広告しておらず、FoamFix 自身が低速経路に落ちる。celtium 側の glCopyImageSubData の配線と単体 pin は入っている。
- **Particle Culling は互換あり**。
- ラスター遮蔽カリング（useRasterOcclusionCulling）の ON / OFF 実走比較で、セクション形状の欠けが無いことを確認した（提示画像の差分はモブの位置・姿勢の時間差のみ）。
- 起動拒否リストと addon 面チェックを実装の現状に同期。Phosphor の拒否メッセージは README と同じく Pulsar を案内するよう揃えた。

### 性能

- hot path の割り当て削減、descriptor pool の成長可能化、viewport / scissor の再利用、粒子再パックのキャッシュ、descriptor set の退役回収など、複数波の最適化が入った。フォントアトラスの集約も実装が入ったが、実測の利得は主張しない。
- 参考値（プロジェクト README の実測表）: 重い modpack 場面 Supersymmetry（188 mods）で Celeritas 2.5.0-dev と比較し、RX 6400 で p50 +2.5% / p95 +7.0%、Intel UHD 630 で p50 +6.4% / p95 +3.1%（いずれも FPS）。この場面では両 GPU とも celtium が上回っている。
- 対照測定（生成ワールドを飛行する場面、koenigsegg-agera / Intel HD Graphics 620、解像度 1280×720、render distance 12、暖機後の窓）: celtium のフレーム時間 P50 は 3 本の実走で 16.55 / 19.04 / 19.00 ms（標本 363 / 331 / 335 フレーム）。同じ場面の Celeritas は約 8.1 ms で、この場面・この GPU ではまだ差がある。パック公開の修正が入った後の main での再測でも P50 17.27 ms（標本 333 フレーム）で、キャンペーン中の変更による回帰は無い。残差の中心はフレーム予算の「その他」区分で、次版以降の主戦場。
- 測定経路自体の修正も入った: 提示画像の診断読み戻し（readback）のスイッチがハーネス設定に届いていなかった問題を直した。初期の非公式な比較値は、この読み戻しが毎フレーム走っていた条件のもので、製品の数字としては撤回済み。
- 生成ワールド飛行の数字は HD 620 での機能環境のもので、RX 6400 での性能の物差しではない。

### リファクタリングと内部整理

- Celeritas からの GL 切り離し3波（PR #426–#428）が本版の土台。GL 依存の分離、不要になった GL クラスの削除、割り当ての削減、翻訳とワーカーまわりの修正が入った。
- 巨大クラスの分割を3波に分けて実施。CeltiumGlStub から FFM アップコールとトランポリンの配管を抽出した。
- 消費者の無い設定オプション6件と、未読の private フィールド3件を削除。高速ブロックレンダラのトグルは永続化されるようになった。
- Embeddium 互換サーフェスのうち参照ゼロに見えるクラス群が、実は Demonica 同梱の Iris から名前でリンクされていることをバイトコードで確認し、削除ではなく pin テストで固定した。
- テストフラグを celtium.validation のマスタースイッチ配下に集約。forge122 のテストスイートを CI で回すよう配線し、孤立していた CPU 契約チェック3件も CI に繋いだ。

### 診断と計器

- 地形パスの GPU 時間（terrainGpu 列）が実走で実際に返るようになった。従来は読み戻しが最新フレームの未確定状態を読んで常に 0.0 に化けていた。提出単位のスナップショット方式に直し、地形パスの GPU 時間をフレーム予算の独立した列として集計するようになった（実走で実値を確認）。
- 空が単色に平らになる問題（Item 535）は、霧の適用と深度テストの両方が悪い状態に揃ったときにだけ起きることを分離実走で特定した（RX 6400 の ATM3 fixture、各条件1回。どちらか一方を解除すればグラデーションは残る）。因子は conjunction として確定し、恒常修正は次版以降。
- アップロードの予約（reserve）にかかる台帳コストを、アップロード時間の集計から分離して測れるようになった（Item 363）。
- パスのタイミング計測のスイッチを HarnessConfig 経由に統一し、計測テーブルをコンテキストスレッドに閉じた。空の census（sky census）に捕捉対象の同一性を出すようになった（Item 383）。
- クラッシュ時の手がかりとして、最後のウィンドウパス開始引数をファイルに書き通すようにした（Item 536）。

### 既知の問題・未成立事項（誇張しないための明記）

- **内蔵の地形影 lookup 単独での暗転は未成立。** lookup（routed shadow pass の深度を地形シェーダが引く実装）の適用カウンタは動くが、提示画像で影の形としての暗転は実測できていない。今回のパック経路の前進とは別の話として切り分ける。
- **床に落ちる影の形は本版では未検証。** 「影とシェーダパック」の節の実測はテクスチャと面の陰影が提示に届くところまでで、影の形の証明レッグは着地後に回す。
- **BSL が真っ黒になる別件が残る可能性がある。** 影の修正は Complementary で実走確認したもので、BSL での実走はまだ行っていない。
- **HUD キャッシュは入っていない。** 実測の結論として閉じた: 実走の集計（生成ワールドの HUD 300 フレーム）ではキャッシュ可能なグループは 575 件中 0 件（0.0%）で、キャッシュの前提が成立しなかった。HUD は従来どおり毎フレーム描画される。
- **看板テキストのバッファリングは未実装。** 支配性の判定（Gate 0、看板216枚の場面と空白対照の比較）で基準を通過しなかったため、実装していない。
- **額縁の地図は、地図が描画に届く前にグループが閉じてしまう問題が残っている可能性がある。** セーブ側の不整合（バニラの定義を超える地図の色インデックス）で出ていた NPE は、セーブを直すことで 270 件 → 0 件を実測した。celtium 側の残件は判別用の計器まで用意してあるが、結論は次版以降。
