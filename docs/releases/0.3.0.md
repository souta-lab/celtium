## Celtium 0.3.0

0.2.5 から 375 コミット（着地 167 件）、372 ファイル、+33,110 / −8,258 行の変更をまとめた版。内訳は、Celeritas からの GL 切り離し3波（PR #426–#428）、2026-11-21 の総力キャンペーン（コード監査で挙がった約87件の所見を全て切り分けて処分）、そしてシェーダパック経路の内蔵パイプライン化の大きな前進。動的光源の利得は実測で立った。シェーダパックの影は、経路が通って地形プログラムが描画するところまで到達したが、提示画像での暗転はまだ実測できていない — 詳細と切り分けの現在地は「影」の節に正直に書く。テストスイートは common 119 / celtium-vulkan 1,064 / forge122 50（版確定時点の合体ゲート）まで育った。

### 修正

クラッシュ・ハング・寿命:

- デバイス喪失で退役した旧デバイス側の GPU 資源が二重に解放され、ネイティブクラッシュし得た問題（Item 529 系）。
- swapchain 取得が繰り返し失敗したときの無限リトライ → 取得側が失敗を上げて上位へ返すように。
- swapchain の生成が連続して失敗し続ける場合に、無言の黒画面のまま固まるのではなく、上限到達でクラッシュレポートを出すようになった。
- デバイスを実際に持たない Vulkan コンテキストの二重破棄。
- コマンドバッファの解放時に、まだ生きている提出を指すフェンスの解放を保留するように。
- 描画セクションの遮蔽探索で例外が出たとき、inFlight フラグが残って画面が固まり得た問題。
- 遅延クリーンアップの破棄処理が、後継デバイス上で走り得た問題。
- キュー競合で同一フェンスの待機が繰り返され、応答が止まり得た問題。
- レンダラの再読み込み（リソースリロード）時の teardown が失敗しても、例外を記録して新しいレンダラの生成を続行するようになった。従来は teardown の失敗がそのままクラッシュに化ける経路があった（#425 の報告を受けた堅牢化）。
- グラフィックスデバイスの生成に失敗した場合のエラーに、結果コード・デバイス名・有効化した拡張と機能・直前のデバイス喪失の記録が同梱されるようになった。報告者との往復なしに原因へ近づけるための変更（Item 529 の報告を受けた堅牢化）。

描画・表示:

- 深度テクスチャをカラーターゲットとして使ったときに検証エラーになる問題（09600 の深度形）。
- チェーンペアのカラーアタッチメントのレイアウト公開が外れ、検証エラー（00344 / 00900）が出ていた問題（実測で 20 件から 0 件）。
- 遠方の葉ブロックが透けて見える問題（葉の描画品質設定が透過処理に届いていなかった）。
- 頂点法線の計算が、設定クラスの読み違いで常に素通りになっていた問題。
- 霧の色の計算で、霧色の緑成分が欠けていた問題。
- 雲の色・明るさが、雲描画の色公開が欠けていて常に白になっていた問題。
- フォントアトラスが世代をまたいで名前を使い回し、文字化けの温床になっていた問題。
- スポーンポータルのアニメーションが、本来の紫色にならなかった問題。
- 額縁の地図が描画されない問題の一因（DynamicTexture の名前解決の不整合）。
- 負の Z 座標で明るさが入れ替わるビット衝突（ライトキャッシュのキー）。
- 統合型 GPU 環境で、描画範囲の頂点インデックスが 32 ビット幅にならず描画が崩れる問題。

mod / GL 互換:

- mod が名前で書いたフィールドが消えていて、mod の初期化が落ちる互換事故（Demonica）。
- 報告スレッド由来の描画 API の穴埋め（glGenBuffers / glBindBuffer / glBufferData など）。
- mod プログラムのリンク成否（LINK_STATUS / VALIDATE_STATUS）と info log が、実際のリンク結果に基づいて返るようになった（LWJGL2 / LWJGL3 の両経路）。従来は無条件に成功を返していたため、リンクに失敗したプログラムが無音で欠けることがあった。
- ブロック描画を BlockRendererDispatcher 経由にルーティングし直した。dispatcher を差し替える mod との互換が回復する（上流 Celeritas の変更の移植）。

### 動的光源（Item 430）

- 動的光源が地形に効かなかった根因（カメラ減算の二重適用）を修正。
- **利得を実測した。** 暗い場面（koenigsegg-agera、Intel HD Graphics 620、torch のある fixture 場面、各条件1回）で、床中心の輝度が OFF 28.62 → ON 52.28（+23.65）。対照として空 +0.06、石の上面 +0.31、床の左端 +2.31、全画面平均は 29.99 → 35.52。光源近くの床だけが持ち上がり、遠方は持ち上がらない — 光の減衰として正しい形。
- これは HD 620 での機能実走の数字で、RX 6400 での性能の物差しではない。
- あわせて、funnel の集計（FUNNEL_SUMMARY）がワールド退出時に印字されるようになった。従来は JVM 終了フック頼みで、計測ハーネスのログに残らなかった。

### 影: 実パックが内蔵パイプラインで走る。暗転は未実測

- Complementary Shaders / BSL の gbuffers 地形プログラムが、GlStub を経由せず celtium 内蔵のパイプラインで翻訳され、描画まで到達する（実走で地形プログラムの描画を確認）。
- 提示画像が単色の虚空になる問題（mod プログラムへの pre-transform の誤適用が原因）の修正が入った。あわせて地形カラーの公開経路の修正が入り、検証エラーのうち COLOR 形の 00344 / 00900 は実測で 20 件から 0 件になった。09600 は深度形を処分し、本版確定直前の実走では BSL で 0 件、Complementary で 10 件が残っている（解消とは書かない）。
- **ただし、提示画像で影の形としての暗転はまだ実測できていない。** 確定直前の実走（koenigsegg-agera、Intel HD Graphics 620）では、BSL は真っ黒、Complementary は霧の中に石柱と床が見えるが、石のテクスチャ・太陽光の lit・床への影の形はいずれも出ていない。
- 切り分けの現在地: G-buffer の読み戻しで、両パックとも地形 fragment が albedo に (0,0,0,1) を書いていることを実測した。色は deferred の読み側ではなく、fragment の書き込み時点で死んでいる。残る判別は fragment の入力側（属性の対応付け）で、修正は次版に回す。
- 内蔵の地形影 lookup（routed shadow pass の深度を地形シェーダが引く実装）も引き続き入っているが、こちら単独での暗転も実測できていない。

### 性能

- hot path の割り当て削減、descriptor pool の成長可能化、viewport / scissor の再利用、粒子再パックのキャッシュなど、複数波の最適化が入った。フォントアトラスの集約も実装が入ったが、実測の利得は主張しない。
- 対照測定（生成ワールドを飛行する場面、koenigsegg-agera / Intel HD Graphics 620、解像度 1280×720、render distance 12、暖機後の窓）: celtium のフレーム時間 P50 は 3 本の実走で 16.55 / 19.04 / 19.00 ms（標本 363 / 331 / 335 フレーム）。同じ場面の Celeritas は約 8.1 ms で、この場面・この GPU ではまだ差がある。パック公開の修正が入った後の main での再測でも P50 17.27 ms（標本 333 フレーム）で、キャンペーン中の変更による回帰は無い。
- 測定経路自体の修正も入った: 提示画像の診断読み戻し（readback）のスイッチがハーネス設定に届いていなかった問題を直した。初期の非公式な比較値は、この読み戻しが毎フレーム走っていた条件のもので、製品の数字としては撤回済み。
- これは HD 620 での機能環境の数字で、RX 6400 での性能の物差しではない。

### 互換性

- **VanillaFix との併用を確認**（起動クラッシュを切り分けて解消）。
- **FoamFix 0.10.15 との併用を確認**（RX 6400、fixture で実走し提示画像は健全）。ただし FoamFix の高速アニメーション経路はこの構成では発動しない — Cleanroom の LWJGL2 層が OpenGL 4.3 / ARB_copy_image の能力を広告しておらず、FoamFix 自身が低速経路に落ちる。celtium 側の glCopyImageSubData の配線と単体 pin は入っている。
- **Particle Culling は互換あり**。
- ラスター遮蔽カリング（useRasterOcclusionCulling）の ON / OFF 実走比較で、セクション形状の欠けが無いことを確認した（提示画像の差分はモブの位置・姿勢の時間差のみ）。

### 診断と内部改善

- 地形パスの GPU 時間（terrainGpu 列）が実走で実際に返るようになった。従来は読み戻しが最新フレームの未確定状態を読んで常に 0.0 に化けていた。提出単位のスナップショット方式に直し、実走（agera、生成ワールド）で集計に実値が出ることを確認した。
- アップロードの予約（reserve）にかかる台帳コストを、アップロード時間の集計から分離して測れるようになった。
- Embeddium 互換サーフェスのうち参照ゼロに見えるクラス群が、実は Demonica 同梱の Iris から名前でリンクされていることをバイトコードで確認し、削除ではなく pin テストで固定した。未読の private フィールド 3 件は削除した。

### 既知の問題

- **#422（RX 7900 XTX で読み込み画面に紫の四角が出る）は未修正。** 切り分けは続いている。本版には PR #426 のアップロードスロット修正が初めて出荷される（0.2.5 には入っていなかった）。これは頂点・インデックス破損の候補機構への対処で、紫の四角そのものへの対処ではない。診断ビルドでの切り分けに協力いただいている報告者へ感謝する。
- **#423（GTX 1650 Ti でワールド作成時に nvoglv64 で落ちる）は報告者の実機での再確認待ち。** 修正自体は 0.2.5 で出荷済み。
- **内蔵の地形影 lookup 単独での暗転は未成立。** lookup の適用カウンタは動くが、提示画像で影の形としての暗転は実測できていない。パック経路の現況は「影」の節のとおり。
- **HUD キャッシュは入っていない。** 実測の結論として閉じた: 実走の集計ではキャッシュ可能なグループは 575 件中 0 件（0.0%）で、キャッシュの前提が成立しなかった。
- **看板テキストのバッファリングは未実装。** 実測（Gate 0）で支配的と示せなかったため、実装していない。
- **額縁の地図は、地図が描画に届く前にグループが閉じてしまう問題が残っている可能性がある。** セーブ側の不整合（バニラの定義を超える地図の色インデックス）で出ていた NPE は、セーブを直すことで 270 件 → 0 件を実測した。celtium 側の残件は判別用の計器まで用意してあるが、結論は次版以降。
