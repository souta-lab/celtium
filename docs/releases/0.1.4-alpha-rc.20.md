# Celtium 0.1.4-alpha-rc.20 — the atlas upload that loses the device is named, not copied

The black-screen logs end on a 4096x4224 font-atlas upload followed by an AMD GPUVM fault at a fixed
address with permission faults and RW=1 - a write past an allocation. Nothing in the log said which
copy did it, and the machine that produced it cannot be reproduced here (the same RX 6400, the same
Mesa 26.2.6 and the same 4096x4224 atlas upload on X11 legs do not fault).

So this build makes the upload say what it writes before the driver sees it: a bounded
`CELTIUM_UPLOAD_EXTENT copy=WxH at x,y image=WxH level=.. texel=..` line for level-0 uploads, and a
refusal - by name, with both extents - when the copy would write past the mirror image. A run that
would have lost the device now reports the copy that disagreed with its image.

Also carries rc.19 (model runs stop re-binding what repeats, consecutive runs share one indirect
range).
