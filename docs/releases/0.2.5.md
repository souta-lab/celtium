# Celtium 0.2.5 — 影描画と堅牢化のリリース

*Released 2026-11-20 · tag [`v0.2.5`](https://github.com/souta-lab/celtium/releases/tag/v0.2.5) · previous [`v0.2.4`](https://github.com/souta-lab/celtium/releases/tag/v0.2.4)*

0.2.4 以後の変更をまとめた正式版です。中心は、Demonica（Iris 系シェーダーパイプライン mod）の影パスの地形描画が影ターゲットへ届くようになったこと、新規ワールド作成時のクラッシュ（#423）の修正と GPU デバイス喪失時の堅牢化を正式版に含めたこと、swapchain 画像の初期化を作り直して Vulkan validation でクリーンな形にしたことです。併せて、複数レンダーターゲット（MRT）対応、動的ライト、地形まわりの性能作業を含みます。

## 影パスの地形描画が影ターゲットへ届くようになりました

- rc2 で残件と書いた「影パスの地形描画が画面側に落ちる」問題を解消しました。影パスは、束ねられたターゲットの深度を共有する chain pair へ地形を描くようになり（項目332）、影パスの有効化はシェーダーパック使用中かどうかをライブに見る信号へ接続しました（項目419）。画面側の主深度を指す候補は main-depth として拒否します。
- 検証フィクスチャ（AMD Radeon RX 6400、Demonica 0.9.1 + Complementary Reimagined r5.9.3 のガード解除ローカルビルド）での実測: パック読み込み後に影パスが有効化され、影ターゲット（2048×2048）への地形描画（ROUTED / DRAW）を確認しました。同じ leg で、提示フレームの健全性（presented 判定 PASSED、単色化なし）も確認しています。
- 影の読み込み自体は rc2 でネイティブ経路に載せたものが土台です（ネイティブ深度コピーの提供 8 回以上・拒否 0）。

## Fixed

- **新規ワールド作成時のクラッシュ（#423、NVIDIA）**: rc2 で入れた修正を正式版に含めました。他の mod がフレームの途中でフレームバッファを作る経路で、失効したフレームターゲット向けに作られたキャッシュが再利用される問題です。キャッシュ項目が構築先（色・深度ビューとサイズ）を記録し、不一致なら退役して作り直します。作り直しが完了できない場合は旧ターゲットを使い続け、ワールド終了時は破棄されたレンダーパスをキーに持つキャッシュを確実に空にします。正直な現状は rc2 から変わっていません: コード監査・単体テスト・CI で確認済みですが、報告環境（GTX 1650 Ti と大規模 modpack）での最終確認は未了で、報告者の実機確認が最終判定です。
- **swapchain 画像の初期化を作り直し（項目515）**: rc1 で入れた「生成時の一括初期化」は、未取得の画像へ遷移する別の仕様違反を生んでいました（Vulkan validation エラー 7 件）。初期化を、画像を取得した後の present 経路の中で行う形に改め、検証 leg（AMD Radeon RX 6400 / Intel UHD 630）で validation メッセージ 0 を確認しました。この初期化経路は #422（RX 7900 XTX でワールド参加時に紫のブロックが出る）の帰属先とされたものです。ただし rc2 の形では報告者の実機で解消していないことが 2026-11-20 に報告されており、本版で初期化経路そのものを改めましたが、**#422 が報告者の環境で直ったとは本リリースでは言いません**。実機での再確認が最終判定です。
- **GPU デバイス喪失時の堅牢化（#425 系、項目416）**: レンダラ再読み込みの後片付けなどで GPU デバイスが既に失われていた場合に、クライアントごと落ちず、失敗を記録して安全側に倒れるようになりました。併せて、クラッシュ時の手がかり（breadcrumb）の記録を拡充し、ログ制限の対象から外しました（項目415）。
- **透過ソートのハング（#424、項目424）**: 非有限な座標を持つ quad があると透過ソートが終了しなくなる問題を修正しました。
- その他: 霧（fog）の属性復元の修正（項目420）、スプライトのピクセルループが透明度の enum ではなく真偽値を運ぶよう修正（項目425）、高いワールドで lattice が例外を投げる問題の修正と影探索 root の再配置（項目493・491）、Iris がシェーダソース末尾に付ける NUL の許容（項目371）、固定機能プログラムの属性読みの修正（項目374）、バッチキャッシュの stale 修正と作り直し前の退役（項目391・398）。

## Performance

- 描画リストの保持（D25）: 地形バッチの組み立てをフレームをまたいで保持します。検証フィクスチャでの計測で、地形バッチ時間は静止時 0.312 → 0.228 ms/frame、移動時 0.497 → 0.213 ms/frame になりました（rc2 で報告した実測）。
- 頂点の compact 化（D23）: 既定の頂点形式が 24 バイトになり、頂点あたりのメモリが 25% 減りました。
- ジオメトリアリーナの要素を primitive 境界へ整列（項目421）、BoxFinder のキーソートからボクシングを除去（項目489、等価性のテスト付き）。
- 対 Celeritas の FPS KPI は今回も再計測していません（実 pack での計測系が未構築のため）。性能の優劣の主張はしません。

## 互換とその他の変更

- 複数レンダーターゲット（MRT）: `GL_MAX_DRAW_BUFFERS` / `GL_MAX_COLOR_ATTACHMENTS` に 8 を広告し、`gl_FragData` の複数出力や複数カラーターゲットへの描画に対応しました（mod プログラムの土台）。
- 動的ライト（D13）: 地形のシェーディング時に動的ライト（手持ちのトーチ等）を反映します（rc2 から。検証フィクスチャの A/B で光源まわりの画素が明るくなることを確認）。
- 起動時の拒否: OptiFine / Vintagium / Relictium が入っている場合は起動時に拒否します（項目311）。
- フレームの render pass を色形式クラスでパラメータ化（項目404）、アイドル時のフレームキャップ（既定 off、項目388）、読み込み後に CPU 側テクスチャデータを解放する census（項目387）、障害時の生存層（ステージゲート、post chain の自己隔離、安全な設定移行、項目327）。
- リリース工程: 配布 jar 内の SPIR-V 再検証（項目353）に加え、patch の台帳とゲート（項目356）を整備しました（工程側の変更で、挙動は変わりません）。

## Known limits

- 製品版の Demonica jar は、そのままでは Celtium に対してシェーダーを有効化しません（Demonica 自身の QuarantineGuard が Celeritas jar のピンを照合するため）。rc1 の記述のとおりです。
- #422 と #423 は、いずれも報告者の実機確認が最終判定として残っています（上記）。
- Windows・macOS での実機描画確認は 0.2.4 から引き続き未実施です（CI のテストスイートは 3 OS で実行されます）。
