## Celtium 0.3.1

A maintenance release for 0.3.0, cut the same day. It fixes two crashes and the Demonica menu corruption, and carries the performance work that landed after 0.3.0. The combined full gate for this release is common 119 / celtium-vulkan 1,108 / forge122 50 — 1,277 tests, zero failures and zero errors (one known skip).

### What you will notice

- **Menus render correctly with Demonica again.** With celtium 0.3.0 + Demonica, the GUI was corrupted — text as white blocks, a black menu background, missing textures. All three causes are fixed (below); proof runs show the title menu, logo, buttons and the options screen rendering correctly with Demonica present.
- **Placing an enchanting table no longer crashes the game.** The same crash hit every tile-entity special renderer whose display list replays through the compatibility path — the enchanting-table book, chests, beds, banners, skulls.
- **Alt-tabbing, minimising or resizing no longer crashes.** A window surface that briefly reports a 0x0 size is now treated as something to wait out, not as a fatal swapchain failure.

### Demonica GUI corruption: three stacked causes

The corruption was not one bug. Three separate defects stacked on the same GUI path, all where Demonica's bundled GLSM layer sits between the game and celtium:

- **(a) Untextured batches were discarded.** When GLSM's textured fixed-function program was bound and a position-only batch arrived, the attribute mapping failed and the batch was refused. Texture-disabled batches now take the built-in pipeline under a bound textured program instead of being thrown away.
- **(b) Textured GUI draws never arrived.** GLSM cancels BufferBuilder draws and reroutes them through its own renderer as VAO-described indexed draws; celtium's stub could not read that layout, so the textured draws (the menu background, the logo, the buttons) never reached the backend. The stub now decodes the VAO-described layout and serves those draws. In the proof runs the draw census matches the call census exactly, with zero refusals.
- **(c) A line-width answer armed a program that could never link.** The stub answered a line-width range that contradicted the real device, which made GLSM enable its geometry-stage wide-line emulation; the resulting program cannot link through celtium's two-stage lowering, and the client crashed in-world. The stub now answers the device's real maximum line width, so the emulation is never armed.

Also in: when Demonica's OpenGL profile resolves to a compatibility context — which latches celtium's honest GL 3.0.0 floor and stops Demonica — the log now prints a hint naming the setting to change (`advanced.opengl_profile` = `CORE` in `config/demonica-options.json`).

### Crashes fixed

- **TESR MemoryStack exhaustion (a 0.3.0 regression).** The immediate flush held a single MemoryStack frame for the whole flush while per-group temporary allocations accumulated without bound, so placing enough tile entities — an enchanting table was enough — exhausted the stack and crashed. The per-group stack scope is restored (the stack cost is now constant in the number of groups, not a bigger stack), and the contract check that guards it is wired back into CI; it had been deleted when the regression was introduced.
- **Swapchain 0x0 crash.** When the window surface pinned a 0x0 extent (minimised, mid-resize, alt-tabbed), swapchain creation was refused, retried, and escalated to a fatal crash after about two seconds. A pinned 0x0 extent is now classified as *awaiting a surface size*: the client waits for a real size instead of escalating. Structural refusals (no usable format, no transfer/composite support) still refuse as before.
- Also in: pack terrain executions are now bracketed by a host-side state snapshot/restore guard, so a pack program cannot leak GL state into the passes that follow it.

### Performance

- **Region offsets through a binding-5 SSBO.** Terrain region offsets are delivered through a shader storage buffer indexed by `firstInstance`, replacing per-draw descriptor work — one descriptor bind per pass. On the landing measurement (agera steady window), the record-bind cost fell by about a quarter.
- **Global vertex/index arenas.** Terrain geometry now goes into shared global arenas with indirect draw chaining inside a pass, instead of per-section buffers. On the landing measurement the per-frame draw-recording cost fell by roughly an order of magnitude on the flight scene.
- **Graphics pipelines are no longer re-created every execution.** Under shader packs, the pipeline cache key included a blend-state object whose hash code changed on every construction, so the cache missed forever and `vkCreateGraphicsPipelines` ran on every execution. The blend state now has content-based equality. Measured on the Complementary pillar scene (PC, RX 6400): pipeline creations fell from 390 per leg (≈4.48 per frame) to 6 per leg.

No general performance-superiority claim is made for this release; the remaining gap on the integrated-graphics flight scene is still being worked on.

### Known issues — stated plainly

- **The BSL black wedge is not fixed in this release.** With a shadow-capable BSL pipeline constructed, an unwritten cone can appear in the presented frame. Every celtium-side observation point has been compared between the broken and healthy configurations and is identical; the remaining locus is driver-side execution, and the investigation is continuing with GPU frame captures. It is not written as fixed.
- **VUID-09600 is not resolved.** A residual of 10 instances still appears in Complementary runs, as in 0.3.0.
- The Xaero minimap report from the same reporter is still being reproduced and triaged; nothing about it is claimed here either way.
