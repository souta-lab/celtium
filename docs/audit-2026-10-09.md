# External audit, 2026-10-09 - findings and status

Fixed HEAD audited: `f3ac1844b`. Findings are reproduced here with what was done about each, so the plan itself stays
short.

## A - P0, confirmed and fixed: `VkSubmitInfo.waitSemaphoreCount` was zero

Verified from the LWJGL 3.4.1 bytecode: `VkSubmitInfo.npWaitSemaphores` writes only the pointer, so a `calloc`'d struct
waits on nothing. Both submission sites now set the count explicitly (`VulkanTerrainGpuBackend.submitCommands`,
`VulkanContext.submitWithSemaphores`); `VkPresentInfoKHR` needed no change because its setter does set the count, which was
also verified rather than assumed.

Measured after the fix: frame present **PASSED, `nativeTerrainVerified True`, 2148 passes, zero validation messages** (36
before). The log's earlier "the layer's view of external semaphores" hypothesis is retracted in the history file.

## F - P1, confirmed and fixed: the harness accepted validation errors as success

`scripts/prism_validation.py` now reads the whole log after the process exits and fails the run if the layer reported any
message, with `validationMessageCount`, `validationClean` and `validationFirstMessages` in the result so the two things the
audit asked to keep apart stay apart. The detection was checked against logs with known contents: the pre-fix probe log
yields 2 messages (so that run would now fail) and the post-fix default log yields 0.

This is the guard whose absence let a PASSED run contain thirty-six messages: the fixture's counters only see the
renderer's own errors, and the layer reports into the log.

## Open from the audit

- **B (P0)** - the present path's shared-image ownership contract: `beginFrameForPresent` signals a GL-to-Vulkan semaphore
  and `presentImage` waits only the WSI acquire; the shared image's real layout and ownership are not handled, the
  render-finished signal is not what `endFrame` waits, and the caller treats a returned failure string as success. The flag
  stays off by default until this is designed and measured on both GPUs.
- **C (P1)** - `Backend.delete()` and the region/texture eviction paths release GPU resources without waiting for pending
  submissions; the audit reproduced the corresponding VUIDs in the reload runs' logs. With waits now real, this matters
  more, not less.
- **D (P1)** - the one-window-per-frame limit defers geometry to the next frame while the batch is still reported as
  accepted and GL's draw is cancelled, so "lag-free" in the plan contradicts the code.
- **E (P1)** - *partly fixed.* `waitForIdle` is now submission-aware and bounded: it returns without waiting when nothing
  was submitted (a failed `vkQueueSubmit` leaves an unsignalled fence behind), it clears the pending flag only after the
  wait resolves, it reports a timeout instead of hanging, and it drains the queue only after the fence actually signalled.
  Measured after the change: default run PASSED, 1633 passes, 0 validation messages, no idle complaints. **Still open:**
  the terrain frame path and the immediate window call `endFrame()` even when both the original and recovery submits fail,
  which signals nothing to the bridge semaphore GL then waits on.
- **G, H (P2)** - diagnostic readbacks on the default path, and the backend not registering itself when timestamps are
  unavailable.
