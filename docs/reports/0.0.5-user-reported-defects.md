## #2a の訂正（2026-10-15・vanilla ソースで確定）

**「blur がかからない」は Celtium の欠陥ではない。vanilla 1.12.2 には blur が無い。**

vanilla の `GuiScreen.func_146270_b`（= `drawWorldBackground`）は、world があるとき
`drawGradientRect(0, 0, width, height, 0xC0101010, 0xD0101010)` を引くだけで、**ぼかしは一切しない**。
world が無いときは `options_background.png` を 32px でタイルし `0x404040` で塗る。
利用者のスクリーンショットの暗いグラデーションは**この仕様どおり**である。

ぼかしは **`tterrag1098/Blur` という別 Mod の機能**で、利用者の 16 mod 構成には入っていない。
したがって **#2a は「入っていない Mod の機能を期待している」**であり、修正対象ではない。
**記録から欠陥として数えない。**

一方 **#2b（ビデオ設定で暗幕すら無い）は実バグ**として残す。

## #5 の見立て（利用者の要求どおり、原理的に可能かを明示する）

**原理的に不可能ではない。** ただし経路が2つあり、どちらなのかを先に確定させる必要がある。

- Cleanroom の起動ロゴは `SplashProgress` 系（Forge 由来）で、**GL で描く**。GL-less 経路には GL context が無いので、そのままでは描けない。**これは「描けない」ではなく「native pass がまだ無い」**。
- 一方で「**表示されない**」という観測は、**描画が失敗している**のか **そもそも呼ばれていない**のかを区別していない。Cleanroom は `SplashProgress.finish()` を早期に呼ぶ経路があり、それが走っていれば**描く機会自体が無い**。

したがって次の順で確定させる:
1. ログに `CELTIUM_SPLASH_HOOK` が出ているか（既存の計器。出ていれば hook は呼ばれている）
2. `SplashProgress` の描画が native pass を持っているか
3. 上記2つで「呼ばれていない」なら**原理ではなく起動順序の問題**であり、修正可能

**「不可能」と断定するのは、1〜3 を測ってからにする。** 現時点で断定しない。

## 共通根因（2026-10-15 に特定）

**#2・#3・#4 は「GUI の下に世界／パノラマが描かれていない」という同一根因である。**

1.12.2 の `GuiScreen.drawWorldBackground(int tint)` は、**world があれば世界の上に暗幕を引き、無ければ dirt 背景を敷く**。
利用者の報告は #2・#3・#4 のいずれも「背景が一様な暗色／単色」で、**世界もパノラマも透けていない** — これは
「暗幕だけが描かれ、その下の世界が描かれていない」形と一致する。#3 のベージュ一色も同じ説明がつく
（Advancement 画面の背景は本来 dirt か世界で、単色ベタではない）。

**パノラマの経路は既に計器を持っている**（だから「無い」ではなく「描けていない」を測れる）:
- `TextureCopyService.java:121` — `GuiMainMenu.renderSkybox -> drawPanorama -> ro...`
- `TextureCopyService.java:320` — 「Which caller issues the copy: the panorama's is `GuiMainMenu...`」
- `TextureCopyService.java:537` — 「`renderSkybox`'s final composite quad likewise: at 38%」
- `VulkanTerrainGpuBackend.java:12457` — 「The main menu's panorama is the measured caller」
- `GllessFrameTarget.java:1011` — 「the main menu's panorama work: `GuiMainMenu.renderSkybox`」

**受入は `CELTIUM_TEX_COPY_SERVED ... mean=` 行**（fixture の `menuHoldTicks` のコメントがそう定めている）。
つまり **#4 は「計器が出ているのに絵が出ていない」なのか「計器も出ていない」なのかで分岐する** — 次にそれを測る。

**#1 は独立**で、アイテム/ブロック entity のテクスチャに filter か mipmap が掛かっている疑い
（地形の atlas とは別経路）。
