# Celtium

An experimental **native Vulkan renderer for Minecraft 1.12.2 on CleanroomMC**, built from Celeritas.

Celtium creates the game window without an OpenGL context, renders terrain, entities, items, particles, sky/clouds and
the GUI into Vulkan-owned images, and presents the finished frame through a Vulkan swapchain. It is a renderer
replacement, not an OpenGL-to-Vulkan translator: native passes follow Minecraft's terrain, model/item, entity/TESR,
particle, UI, texture and framebuffer semantics.

> **Status: experimental, 0.2.0 (2026-11-04).** Rendering fidelity and error-free operation improved a lot in 0.2.0,
> but the performance goal is **not met**: the paired KPI against Celeritas is **1.189** (`NOT_MET`). Complete modpack
> compatibility and all-scene correctness are not claimed. The single current status table is
> [docs/plan.md](<docs/plan.md>); release notes are [Japanese](<docs/releases/0.2.0.md>) /
> [English](<docs/releases/0.2.0-en.md>).

## What's new in 0.2.0

- **The build works again** (Lombok annotation processing, upstream metrics accessors, mixin annotations), and a
  **CPU verifier for transformer-generated bytecode** loads 241 real LWJGL declarations and 87 real GL classes.
  It found four runtime VerifyErrors, one of which made GL20C itself unloadable.
- **Indexed drawing** (client/VBO vertices, client indices, baseVertex, multi-draw, instance=1, 12–32-byte layouts),
  **legacy immediate mode** (glBegin/glEnd) by default, and **quad-strip/polygon** conversion.
- **Menu/title/pack-menu art**, **creative-screen icons**, **tooltip motion**, and model replay are measured and fixed.
- **Large GL-surface repair**: display lists, pixelStore, buffers, textures, FBOs, shader getters, pname mix-ups,
  uninitialised outputs, write overruns, per-VAO attributes, push/pop stacks, light/fog/material and binding queries.
- **Performance measurement**: same-JAR/same-leg A/B, a control arm that cancels machine drift, JFR profiles, and
  window/group/accept-path breakdowns.

Full list: [0.2.0 release notes (English)](<docs/releases/0.2.0-en.md>) ·
[Japanese](<docs/releases/0.2.0.md>).

## Requirements and tested environment

| Component | Current requirement / verification |
| --- | --- |
| Minecraft | 1.12.2 |
| Loader | CleanroomMC **0.7.12-alpha** (SDL 3). Builds detect the SDL 3 binding and refuse to start on the 0.6.x GLFW generation by name. |
| LWJGL | LWJGL3 **3.4.3** (the SDL 3 generation Cleanroom 0.7 ships). Celtium bundles the matching `lwjgl-vulkan` Java bindings; LWJGL core, SDL and native libraries come from Cleanroom. |
| Java | **JDK 25** to build (RetroFuturaGradle 2.0.4); the verified gameplay JVM is **Java 27**. |
| Celtium module bytecode | `--release 21`, class major 65 or lower. |
| Vulkan | 1.2+ loader and physical device with the required graphics/presentation, format and resource capabilities. |
| Verified GPUs / OS | AMD RX 6400 (RADV NAVI24) and Intel UHD Graphics 630 (CFL GT2) on Linux/Mesa. |
| Other GPUs / OS | NVIDIA, other AMD/Intel models, Windows and macOS are unverified. |

Vulkan 1.2 support alone is not a compatibility guarantee; features are selected by device capabilities, not GPU name.

## Install

1. Prepare a Cleanroom Relauncher instance (Cleanroom 0.7.12-alpha, LWJGL 3.4.3, game JVM Java 27).
2. Put `celtium-forge-mc1.12.2-0.2.0.jar` into `mods/`. Use the plain jar, not `-dev` or `-reobf`.
3. Remove Celeritas: **install one renderer, not both.** The internal mod ID and resource namespace remain `celeritas`.
4. Use [Pulsar Lighting Engine](https://modrinth.com/mod/pulsar-lighting-engine), not Alfheim (Alfheim is unsupported).
5. Start the game, enter a world, and check GUI/menu/creative/tooltips.

Download: [Celtium 0.2.0](https://github.com/souta-lab/celtium/releases/tag/v0.2.0)
(sha256 `bf1193b6ba21dc51cd36a5b013607dd58a9ef8bcbc516ca8f24b0c247e9cccee`).

## Scope and compatibility

- **Minecraft 1.12.2 / CleanroomMC only.** Stock Forge with Java 8/LWJGL2 and other Forge + LWJGL3 replacement stacks
  are not supported.
- Ordinary gameplay/content mods are a compatibility goal. Compatibility is **not yet complete**; tested mods are in
  [verifiedmods.md](verifiedmods.md), refused/known-broken mods in [notworkingmods.md](notworkingmods.md).
- **Competing renderer replacements are not supported alongside Celtium.**
- Shadows and shader packs are not part of Celtium itself: they are planned as a separate addon jar (a Demonica fork,
  AGPL-3.0). Vanilla ShaderGroup, spectator effects and entity outlines remain part of the base renderer's scope.
- **GL-less is installed from the coremod transformer chain**, immediately before the window is created. The glstub
  applies only to mods that call GL directly; it is not applied to other mods.
- Mesh shaders are not required or planned. Optimizations must preserve a usable baseline on weaker GPUs.

## Performance

### Current paired KPI against Celeritas (0.2.0)

Measured on the **same Cleanroom Relauncher modpack instance as the tester**, `celtium-world-accept`
(**192 mods**, save `qmagnet`), not a bare client. Scene `world`, pose `x=217.5 y=48 z=217.5 yaw=180 pitch=10`,
`guiScale=3`, `renderDistance=12`, `maxFps=260`, vsync off, 1280×720. Each leg runs 240 s; the warm window is world
ticks 400–600. KPI legs run **validation off** to remove the measurement tax; clean-validation evidence comes from
separate validation-on legs. Celeritas 2.5.0-dev is the reference; the control arm is the round-58 build.

| rep | Celtium p50 | Celeritas p50 | ratio | vs past build |
| --- | --- | --- | --- | --- |
| 1 | 2.742 ms | 2.332 ms | 1.176 | 0.985 |
| 2 | 2.869 ms | 2.413 ms | 1.189 | 1.063 |
| 3 (load contamination) | 3.620 ms | 2.311 ms | 1.566 | 1.380 |
| **median** | | | **1.189** | **1.063** |

`goalCondition=NOT_MET`. The two clean reps are 1.176 / 1.189; against the round-58 build they are −1.5% / +6.3%, so the
past-build comparison is within run-to-run noise (identical-code legs drifted 9–15%). The remaining gap is CPU-bound:
frame 1322 µs = world 861 + gui 421 + hand 50, and 85% is Celtium's immediate path (accept 648 µs + flush 392 + guiFlush
81). Windows open on framebuffer bind. Remaining levers: a per-bind sampling census, bracketing the accept path,
bindless immediate textures, and a second open group for opaque depth-writing unblended groups.

## Known issues

- **FPS is 1.189 against Celeritas and not met.** The accept path and windows remain; Intel's p99 (1.048) is also
  unresolved.
- **Menu/tooltip/creative tabs** are confirmed by scenes but need a re-check in the tester environment.
- **Not implemented**: cube maps / 3D textures / MSAA / compute / blit / copyImage / some DSA / stencil
  (ModularUI's Stencil#reset uses mask 0x400).
- **Real legs depend on the environment**: they rely on the verification harness's Prism instance layout. The
  distributed JAR needs a separate tester check.
- **Shadows/shader packs**: a separate addon built from the Demonica fork; not part of core.

## Building and testing

Run Gradle with JDK 25. The build also uses the JDK 21 compilation toolchain and the JDK 8 Minecraft preparation
toolchain.

```sh
JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 scripts/build.sh
```

The packaged jar is written under a directory named after the version:

```text
build-1122/build/libs/0.2.0/celtium-forge-mc1.12.2-0.2.0.jar
```

Use a separate Cleanroom test instance and install the plain jar instead of Celeritas.

CPU checks (no GPU):

```sh
python3 -m unittest discover -s scripts/tests -p 'test_*.py'
scripts/cpu-contract/transformer-route-verify.sh
python3 scripts/check_agent_docs.py
python3 scripts/instrument-index.py --check
```

For reproducible validation and development, use [the current development procedure](<docs/development.md>) and the
tracked [leg runner](<scripts/gv-leg.sh>). [AGENTS.md](AGENTS.md) contains working agreements.
